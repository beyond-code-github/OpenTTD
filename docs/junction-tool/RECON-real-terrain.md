## 1. How JunctionTerrain is filled today
- Struct: src/junction_terrain.h:21-28 (tile: z_min, z_max, steep, incline, canonical slope, cls, clear_cost); :48-55 (grid: origin, width, height, tiles, foundation_cost, build_on_slopes, max_bridge_height). Classes :15-20: Buildable, Water, Spannable, Blocked.
- Filler: `FillJunctionTerrainCell` src/junction_game.cpp:295-327. z_min from GetTileSlopeZ, z_max GetTileMaxZ, steep, incline, canonical slope (:297-303).
  - Clear/Trees: runs LandscapeClear with QueryCost (:233-236, :307-314); Buildable with clear_cost if it succeeds, else stays Blocked.
  - Water tile -> Water (:315). Plain rail -> Spannable (:318). Normal road / level crossing -> Spannable (:321). Everything else (houses, stations, industry, objects, depots, bridges...) -> Blocked (:324, default cls set to Blocked at :362/:402).
- Settings from `_price[BuildFoundation]`, `_settings_game.construction.build_on_slopes`, `max_bridge_height` (:332-337).
- Entry points: `MakeJunctionTerrain` (:350, anchor/rotation/mirror/frame/margin; used by junction_gui.cpp:555,656 and console_cmds.cpp:405) and `MakeJunctionTerrainRect` (:385, map-axis rectangle, rotation 0, for the line painter). Cells off-map or invalid tile are Blocked (:373-376, :410-413).
- Not captured: ownership (all non-clear tiles Blocked regardless of owner), tile type for Spannable (rail vs road), tree density (only via clear_cost), coast/shore detail beyond class Water, bridges/tunnels ends, rivers vs sea.

## 2. Can openttd_test generate a map with TGP?
- Test target: CMakeLists.txt:247 `openttd_test` links `openttd_lib` (:291), so all game code incl. tgp.cpp, landscape.cpp, genworld.cpp is linked (INFERRED that nothing is excluded; not checked per-file). test_main.cpp is plain Catch2 main, no driver/init (src/tests/test_main.cpp:8-14).
- Existing map use: tests only call `Map::Allocate(64,64)` etc. (e.g. src/tests/junction_gui.cpp:29, junction_game.cpp:215/253/315, junction_map.cpp:824 with 256x256) giving an all-clear height-0 map, then poke tiles by hand (junction_game.cpp:245-262). No test calls GenerateWorld/GenerateLandscape/GenerateTerrainPerlin (grep of src/tests found none). Existing "terrain" in tests is synthetic: `MakeRidgeTerrain`, `MakeTownHillTerrain`, `BlockMapTestTile` (src/tests/junction_map.cpp:306, :820-830) building JunctionTerrain directly.
- Full `GenerateWorld` (genworld.cpp:291) is NOT test-friendly: it runs InitializeGame, progress windows, SetObjectToPlace (:107), StartupEconomy/Companies/Engines (needs engine/newgrf data), Game::StartNew, 0x500 tile loops, and may SwitchToMode (:229). Needs a video-less but GUI/progress-aware init. INFERRED: would crash or need heavy mocks in openttd_test.
- Landscape-only path is lighter: `GenerateTerrainPerlin` tgp.cpp:1057-1087 (AllocHeightMap, HeightMapGenerate, Normalize, write heights via TgenSetTileHeight) needs: `Map::Allocate`, `_settings_game.game_creation.{land_generator=LG_TERRAGENESIS, landscape, tgen_smoothness, variety, ...}`, `_settings_game.difficulty.terrain_type/quantity_sea_lakes`, `_settings_game.construction.freeform_edges`, `_random.SetSeed(seed)` (genworld.cpp:103), and `_generating_world`/progress calls (IncreaseGeneratingWorldProgress at tgp.cpp:1065,1069 - INFERRED safe with no progress window, not tested). Then `GenerateLandscape` (landscape.cpp:1618-1716) adds FixSlopes, ConvertGroundTilesIntoWaterTiles, CreateRivers. Heightmap loading (GWM_HEIGHTMAP, landscape.cpp:1628) needs a file + `_file_to_saveload` (not trivially available in tests).
- Land-only still lacks towns/trees (those come from genworld.cpp:140-150: GenerateClearTile, GenerateTowns, Industries, Objects, Trees). Town gen needs town names, house specs, road types (CheckTownRoadTypes genworld.cpp:111) -> INFERRED heavy for unit test.
- Verdict: feasible with effort for terrain only (risk: global state, settings defaults, `_generating_world`), fragile and slow-ish for towns. Not recommended inside openttd_test.

## 3. Alternatives and existing rig tooling
- Rig: tools/ottd/ottd (CLI), ottd_core/server.py:106-140 starts `openttd-spike` dedicated with `-D -c <cfg> -g -G <seed>` (seed env OTTD_RIG_SEED, default 3); `--hilly` writes terrain_type=3, variety=2, smoothness=1, lakes=2, towns=4 (server.py:112); default is flat (terrain 1). `--save PATH` loads a save instead. README: tools/ottd/README.md (start/stop/rcon/gs/junction-here/junction-scan with random spots; "Flat ground" section; `rcon "save NAME"` writes <rundir>/save/NAME.sav; `screenshot heightmap` works headless).
- Console: `junction_export <tile> <rot> <mirror> <path> ...` (src/console_cmds.cpp:322-442) calls MakeJunctionTerrain (:405) and writes the *layout* JSON only. No command dumps the terrain.
- Layout JSON (tools/ottd/layouts/*.json, README "Layout JSON") is tracks/bridges/signals only; src/junction_map_export.cpp has no terrain serialisation (grep "terrain" there: nothing relevant). NO terrain JSON format exists today (searched tools/ottd, src for terrain serialisation; only junction_terrain.h itself).
- Savegame in tests: INFERRED possible via the loader (SaveOrLoad) but needs full game init; heavy. Rejected.
- So the practical route is: dump snapshots once from a real (dedicated, seeded) game via a new console command, check fixtures in, and load them in tests with a ~40-line parser. Do not touch the running game: use a separate port/rundir (OTTD_RIG_PORT, OTTD_RIG_GAME_PORT, OTTD_RIG_DIR env, README) when generating.

## 4. Towns, houses, water, trees
- Real games (genworld.cpp:140-150) include towns, trees, industries, objects, rivers (landscape.cpp:1714). `--hilly` rig config sets towns=4 (server.py:112).
- JunctionTerrain classing: houses, industry tiles, stations, objects, depots, tunnels/bridge heads, owned/unclearable -> Blocked (default branch :324). Trees -> Buildable with clear_cost (:307-314; unclearable if removal fails). Rail/road -> Spannable (:318-322), incl. town roads (so town streets become spannable, buildings blocked). Sea/lake/river/canal -> Water (:315). Coast tiles = Clear with slopes (water flooded tiles are Water).
- Caveat: Clear tiles with a company-owned fields/rocks still cost via QueryCost; town-owned trees/ownership at OWNER_NONE during tests: the query uses `_current_company` (INFERRED: must be a valid company or OWNER_NONE; the dump runs in a live game so fine).

## 5. Recommendation
Dump-once fixtures, replay in tests (INFERRED design, not built):
1. New console command (or admin/GS-free rcon) `junction_terrain_dump <x> <y> <w> <h> <path>` in src/console_cmds.cpp (next to junction_export), calling existing `MakeJunctionTerrainRect(a, b, 0)` (junction_game.cpp:385) and writing JSON: `{origin:[x,y], size:[w,h], foundation_cost, build_on_slopes, max_bridge_height, tiles:[[z_min,z_max,slope,steep,cls,clear_cost]...]}`. ~50 lines.
