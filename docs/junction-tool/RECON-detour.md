## 1. InsertJunctionDetour (junction_nodes.cpp:1920-2022; decl junction_nodes.h:244)
Input: a state LAYOUT, its template, a free X link, a layout column, side +-1, spec.
- Refuses (:1927): link not free, or diagonal, or axis != X, or side not +-1. Y links are never detoured (DESIGN-N3 §5 "stays on X links").
- Refuses (:1936): column not strictly inside the link (lo = min x + 1, hi = max x - 1 of the link's end points p, q).
- Hands (:1940-1949): probes RasterizeJunctionRoute({p.tile, p.trackdir, "FLFRF"}); if the last piece is not on row+side, tries "FRFLF"; else "no S-bend to that side". t1/t2 = the first/second hand.
- Program (:1983): F^n1 t1 F t2 F^n2 t2 F t1 F^n3: out S-bend (two 45-degree curves with one diagonal half piece between), n2 straight pieces on row+side, back S-bend. n3 is derived so the route ends on q with q's trackdir.
- Choice of lengths (:1986-2018): n1 from the link length down to 0, n2 from 0 up; first pair with: raster error-free; last shifted piece + 3 < piece count; no piece on the link row at or beyond the column (in travel direction d) before the last shifted piece ("clear"); some shifted piece on row+side at exactly `column` ("covers"); closing run ends on row, q's trackdir, n3 >= 0; then build() succeeds. So: the LATEST possible out-bend (n1 max) and the SHORTEST shifted run that covers the column; one detour per link and column.
- build() (:1957-1980): copy layout; clear Track::X on the link's interior tiles (row, lo..hi); drop empty tiles; strip first/last piece of the raster (p, q stay) and its bridges; refuse "collision at x,y" if any raster piece's tile is still occupied by ANY track (so a parallel line on row+-1 blocks, and so does the line's own diagonal tiles); AddRasterToLayout; then NormaliseJunctionLayout + BuildJunctionNodeTemplate on a copy: refuses "template error: ..." (comment :1966: a shifted run of one piece has no free link, so the two S-bends form one rigid class and their curve gap cannot stretch).
- Helpers: RasterizeJunctionRoute, AddRasterToLayout, NormaliseJunctionLayout, BuildJunctionNodeTemplate. No signals/slots are touched: layout is track-only.
- Not checked in the function: heights, fits, curve gaps (only through the template's rules in the next solve), tiles outside the snapshot (the solve reports Edge).

## 3. Rule constraints on the edit
- Curve gaps (junction_chain.cpp:25 JunctionCurveGaps; used in the template builder junction_nodes.cpp:466): n = 2 tl, cl = DeriveCurveSpacing(reference_speed, curve_speed, tl); consecutive curves of opposite hand: gap 2 (units); same hand: min(n-1, max(2, cl)); curves j-i apart: min(n-1, (j-i) cl). The S-bend contributes four curves per path (test :655 expects a chain with 4 curves): t1 t2 | t2 t1. Pair (t1,t2) opposite: gap 2 = a 1-diagonal S-bend (rigid, 2 halves); (t2,t2) across n2 shifted run: same hand, needs min(n-1, max(2,cl)) units, so the shifted run must be long enough (this is what makes n2 >= 1 or more at high speed; a run of one piece "has no free link" -> template error, :1966, the case that makes a naive n2 = 0 fail). (t1, t1) at distance 3 apart: min(n-1, 3 cl) over the whole bend.
- Slots/signals: none in the detour; the search is track-only (signals come after, PlaceJunctionSignals/FinishJunctionCandidate in the solve). keep_slot (:491-505) keeps a slot inside its own free link; on the graph path the slot rule is geometric over routes (RECON-graph-input Q5), so the new pieces get slots from the route.
- Template meaning of the edited run: the original free X link is replaced by: free X run (n1) -> rigid diagonal link (S-bend out, 2 halves, one row) -> free X run on row+side (n2) -> rigid diagonal (back) -> free X run (n3). Points are created at every run boundary (ReadPoints :134-170: first/last piece of a direction run). Rigid diagonals fix dx = dy = 1 per row (units 2 per row, DESIGN-N3 §4); the shifted run is a free X link on a NEW Y class (row+side) while the end runs keep the old Y class; so the Y system gains one class per detour and the avoid facts (Straight/Break on the column) now apply to the free shifted run. Free diagonals (>= 3 halves, DESIGN-N3 §6) do not occur here (S-bend diagonals are 2 halves).
- Minimum run lengths: nothing is stored; lengths n1, n2, n3 are the rasterised numbers at the CURRENT positions; the solve then re-stretches free runs. Only "covers the column", "clear before the column" and the curve gaps matter.

## 4. A run in the routes (junction_topology.cpp:1670-1860; tag decl junction_topology.h:250)
- Tags are per piece. A run = consecutive pieces with token == RUN and the same (edge, run, copy); run k lies between tokens k-1 and k (k=0 before the first token; k = tokens.size() after the last; set at :1840-1855 from the preceding token of the same edge). The 'F's of a run are appended as `before` pieces of the next bend/bridge (:1717, :1744, :1785) and the tail run to the out port (:1804). A bend gives halves tags token t, then ONE closing axis piece tagged RUN run t+1 (:1788).
- A run holds: its piece list on each route, hence first/last piece (tile, trackdir), row (Y fixed) or column, axis, direction. It does NOT hold: the neighbouring tokens (get them from programs.edges[e][k-1], [k], and spans in placement.edges[e]), bridges over the run's row (placement.bridges, structure.bridges crossing edges: a run on a bridge head line or under a bridge is rigid, DESIGN-G1 §11.8; its pieces under a bridge (Under token) are not detourable), the doubled-copy relation (copy 0/1 share nothing but a detour must hit both copies when the edge is shared by paths: tags are per route, every path through the edge must get the same insert), the other routes on the row beside it (collision test: layout tiles of the other routes on row+-1 within the column range, incl. node tiles and prio rows), and the box (size, MinX-1 as Edge failure).
- Shared edges: one edge is walked by several paths; the edit must be applied to each route that uses (edge, run), identically, or the shared track diverges.
- Where to insert: in the route builder the run is only the count `before` (':1717/:1744/:1785/:1804'). The edit can split that F-count: F^a, then the detour moves, then F^b (tagged: SBend halves with the run's own edge and new sub-run indices; see Recipe).

## Recipe for a graph detour edit
Data on the state (position-free, D214 item 8): `struct JunctionDetourEdit { uint32_t edge; uint16_t run; int8_t side; uint8_t copy_mask /* or all copies */; int32_t column; /* a placement column (layout x of the failing tile) */ }`, kept sorted (state key = sorted edits; replaces NodeStateKey). Optional n1/n2 only for display; do not store lengths (the old function recomputes them).
Where to realise: RenderJunctionTrackPlacement's route loop, at the points that append `before` F pieces for a run (:1717, :1744, :1785, :1804). Given the run (edge e, run k) with its start cursor `cur` and heading h and end target (the next token's first axis tile, or the out port): for each edit hitting (e, k) on this route, replace "F^m" by F^n1 t1 F t2 F^n2 t2 F t1 F^n3 with m = n1+n2+n3+6 (the S-bend 'F's counted as the old function's program; check: the old program covers the same tiles as the link between p and q), tagged {e, RUN, run k, copy} for the F's and SBend-halves tagged with a NEW token kind so the template knows them (either synthetic token indices >= tokens.size() on a detour sub-edge, or a flag on JunctionTrackPieceTag; the old DetourEdit adds two ordinary SBend tokens to the edge's program, which is cleaner: programs.edges[e] gets 'SBend hand0 / SBend hand1' tokens inserted at position k, then placement must size them). Recommended: insert tokens into the program (restart at programs -> placement), because the tags, run indices (k shifts), lane copy rules and JunctionRouteEvents stay consistent, and the §13.8 item 2 classification says a local edit may restart at the template only if the shifts are not renumbered; take the cheaper "restart at template" only if the render takes the edit directly (then the tags for detour pieces: edge e, token = tokens.size() + 2 i, run k).
Lengths: choose n1, n2, n3 from the placement's current tiles exactly as the old loop (latest out-bend, shortest covering run): they are a function of the run's p/q tiles and column, so the render can recompute them every time; because the placement is solved on the base graph, the child's first solve uses these lengths, and the template then frees n1, n2, n3 (free X links) and keeps the diagonals rigid.
What the template sees: five links where there was one (free X, rigid diagonal, free X on a new Y class, rigid diagonal, free X); a new Y class; curve gaps among four new curves; the avoid fact on the shifted free link at `column`. JunctionNodeInputOfGraph needs no change if the routes are right (tags carry through; it builds events/slots by its own rules).
Refusals to keep: not an X-axis run (Y runs: no repair yet); column not strictly inside the run; collision with any track already on the new tiles (the routes of other paths, bridge heads, the run under a bridge); shifted run of 1 piece (template error); side with no S-bend; outside the box (Edge). Also reject a run whose tokens neighbour: an Under/Over adjacency within the run (rigid).

## Open questions
1. Detour on a shared edge: all copies/paths must get it. Is an edit keyed (edge, run) enough, or does a run on a copy-0/copy-1 doubled edge need two edits? (Proposed: one edit applies to every route through the edge, on both copies, which both must then have free room on their rows.)
2. Tokens vs tag flag: does P4b insert SBend tokens into programs (restart at placement, needs the placement code to size them, RECON said S-bend size iteration is fragile, FABLE-G1c2 §11.9b) or render directly (restart at template, tags with synthetic tokens)? Decision for Pete/orchestrator.
3. The failure column is a working x; an edit needs a placement/graph-coordinate column that survives replacement of the placement (D214 item 8 "position-free"): store the failing piece's (edge, run, index within the run) rather than a column, and cover it by the shortest S-bend that passes it? Not the same as a column when the run moves.
4. Collision rule: the old build() refuses ANY occupied tile. On the graph path the tiles are not known until placement; the child's solve (Occupancy failure) must name both elements and the repair must then try the other side; today there is no Occupancy repair.
5. HeightsOk and the fits loop assume a layout and T movements; the graph version must run them on routes (tagged pieces): fits per tile from routes' track union; heights per route piece. Failures there are dropped today; item 7 of §13.8 asks what happens.
6. Cost: no terraform price function in junction code (D190/D196 TF1); the detour state cost (rail_piece + turn_cost per curve) is a model, and D198's bound needs a floor; to decide before P4b.
7. Dedup: the layout key goes; with an edit list a canonical key is (sorted edits); two edits on one run at different columns (n runs) are not a one-edit state; today a child replaces the detoured run's interior and the detour's own sub-runs are separate free links, so a second detour on the shifted run is possible (nested). Allowed or not?
8. Max states 16 and the best-first order (detours count) are not costs: switching to cost can change which house/hub-tile result is returned; the [nodeoracle] sweep numbers (accepted/heights/fits) are the regression to compare.
