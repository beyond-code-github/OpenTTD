G1 makes that reference a computed output, never a drawing.

## 2. Structure rules (each with its source)
- **R1 Lane expansion.** Through movement main->main: lane i -> lane i, straight (RECON-llrr-facts §3). Exit main->branch: every lane of the direction splits toward the branch (D187); the legs merge (plain lane merge, no prio) before the branch port. Join branch->main: the branch track splits into one leg per main lane (1-to-2 fan, D186), each leg joins its lane with its own prio. A line-choice split has a signal right after it (D192). No shifters (D191).
- **R2 Bridge doubling.** A main-line lane carried over a crossing gets a doubling fan (split, two equal bridges, merge; D80), per lane (D188: four bridges for LL_RR). A non-main bridge is single (D174).
- **R3 Node order along a line.** Splits before merges (D189). Among the splits of one lane: by the side their legs leave towards, nearest first (INFERRED from the T: A splits to S before nothing else; W splits to S then the lane split; to confirm on LL_RR).
- **R4 Crossings.** Two paths that share no node cross iff their end ports interleave around the box boundary (chord rule on the port slot order); exactly one crossing per interleaved pair (minimal). Paths that share a node (split/merge) and swap sides after it also cross once (INFERRED; check on LL_RR's fan legs, where inner-lane legs must pass the outer lane: a diagonal cannot flat-cross an axis track in the game, so it is a bridge).
- **R5 Order of crossings along a path, and of elements on a row.** From a straight-chord embedding of the ports on the box (positions from the port order and the spec gaps): the order of intersections along each chord. Replaces "flat x order" in occupancy (DESIGN-N3 §7) for generated templates. OPEN-1 below.
- **R6 Turns.** Per path, the heading at its in-port and out-port gives the net turn: 0 (through, S-bends only), 90 left/right (a corner: two same-hand 45-degree curves, diagonal of odd half count >= the curve rule, RECON-turn-programs §2/§5). Row changes along a line (to a lane row, to a fan leg's row, past a bridge) are opposite pairs (S-bends, DESIGN-nodes §4b).
- **R7 Sides.** A split's leg leaves toward its destination side. Prio rows: at main-line merges, on the side away from the joining leg where space permits (D28 and its "wherever space and cost permits" ruling).
- **R8 Lengths are constraints, never values.** Curve gaps (N0a), prio coverage (D108/D148), D113 signal pieces, whole-train bays D176 (OPEN-2), D145 lane constants, bridge spans and D172 windows, port stubs D115a, port approaches D179, box edges. All are today's template rule kinds; G1 emits them from the structure.

## 3. Reference positions
- The structure's constraints over X and Y classes are difference constraints, so their least solution (every class at its lower bound, JunctionPositions after AddJunctionNodeConstraints; min-closed, DESIGN-N3 §7) is a consistent assignment by construction: the reference. Lengths not bound by any rule take their minimum (RECON-turn-programs §3: "slack from the frame" disappears).
- From the reference the builder renders each path as a piece sequence (run directions and lengths are known) and hands it to the rule builder (split from the tracer, step G1b), which produces the template exactly as today. The reference is the template's `flat`.
- Consequence: the generated T is more compact than today's flat T where today's has frame slack (A west of the split 23 tiles, etc.). The oracle comparison is therefore structural (§5), not tile-equal.

## 7. G1b(ii) split and the track graph (orchestrator, 2026-11-12)

- **Trees (R1, R3; D187, D204).** Each in slot with two or more paths gets a split tree: first by the far slot's group (direction), then by far slot (lane); each out slot a merge tree, mirrored. Children in counter-clockwise order of their least far slot ((far - slot + n) mod n). Two legs per switch; more is refused ("not ruled yet"). Splits before merges along every path follows: a path is its in tree's edges, its own leg, its out tree's edges.
- **Crossings per edge (R4 per edge, FABLE-G1 §1b).** Candidate pair = two edges with disjoint path sets where every path pair between them is a chord crossing. Greedy by bundle product, largest first, ties by edge index; a candidate is taken when none of its path pairs is already covered. Legs always cover what is left, so every chord pair is crossed exactly once. Default = fewest physical crossings; crossing on legs instead is a later cost choice.

**10.1 Program grammar** (RECON-turn-programs §1 writes every T path this way). A path = Runs joined by bends. Run {heading E/W/N/S; events in order: node, bridge over, passing under, port}. Corner {to heading, hand}: a 90-degree same-hand pair, odd halves >= the curve rule (D1, D3, D5, D7). SBend {side, rows or columns}: an opposite-hand pair moving the line sideways (an S-bend; NOT a shifter, D191), 2 halves per row (D6, D8-D11; D2/D4 move columns). Lengths are not part of a program.

**10.2 Rules from the structure (S-side branches).**
- Main lane, through: Run on the port row; in the W/E fan zone a S-bend to its stack row; Run on the lane row with its events; S-bend back to the port row in the far fan zone; Run to the port.
- Fan zones: between each box side's port stubs and the first node or bridge of any lane on that side; only lanes there. Port rows = the notation rows (D38/D142) placed to minimise the largest lane S-bend (ties: north). Lanes S-bend outward monotonically (north lanes up, south lanes down), so the fan's diagonals never cross.
- Doubling (crossed lane leg, D80/D145): the leg's path gives two copies: the lane copy keeps the lane row through the bridge; the side copy S-bends to the copy row (copy side, §9) at the lane split, bridges, S-bends back at the lane merge. Both bridge over the row's crossing set (one bridge per crossed row edge, §9). Lane split/merge are new nodes (decoration).
- Exit leg leaving a lane split: Corner toward the branch side (heading E: right; W: left) to heading S; then a Y Run.
- Joiner reaching a lane merge: Y Run north to its approach row (§9), Corner to the lane's heading, Run on the approach row, S-bend into the lane at the prio merge (D75: the merge sits inside the S-bend, D6/D8).
- Branch node (band): one child continues the Y Run, the child whose far end is farther from the S edge (smaller level); tie: the west one. The other child diverges with a Corner if its next heading differs (it leaves for its approach row: P7 at the N split, Je2), else with a S-bend into its own column (P5's D4 into the S merge; J_w at the Bin split; Xe2 into X_e's column). An edge with both ends in one band is that S-bend.
- Crossings: a main-lane bridge is on the lane's Run (both copies); the crossed Y Run passes under. A band crossing (§9) is a single bridge on the joiner's Y Run.

**10.7 Programs, settled for G1c(i-a) (orchestrator, 2026-11-12).** One program per graph edge (paths share edges, so shared track is drawn once); a doubled edge has two (copy 0 keeps its upstream row through the bridge and bends onto the lane row after it, the T's lane A; copy 1 bends onto the lane row before the bridge, lane B; F5). A program is a token list in travel order: Fan, Corner, SBend (bends) and Over, Under (crossings). Runs are implicit between tokens; lengths, columns, band y order (F3), band slots (F1), signals (F7) and port rows are not in it (G1c(i-b), (ii)). Token order is topological: a bend's tail may overlap a row it is listed before or after (F6); (ii) decides.

A row is doubled when its leg carries a doubled bridge; its upstream edge then runs on the row's north item (copy row), the leg's copies and the Out edge end on the lane item. In: Fan(upstream item). Out: Fan(lane item). Fan = the S-bend between the port row and that item, possibly none (port rows are placed in (ii)); hand 0.
- Doubled leg: copy 0 = Over(x) for each crossing in travel order, then SBend onto the lane item; copy 1 = that SBend first, then the Overs. Hand: north to south = +1 heading E, -1 heading W.
- Exit leg (row split to band node or S port): Corner off the lane (heading E: +1; W: -1), to heading S.
- Joiner leg (band node or S port to row merge): Corner onto the merge row's approach item (to E: +1; to W: -1), then SBend onto its lane item (south to north = -1 heading E, +1 heading W). D75: the merge is the SBend's last half.
- Band nodes: siblings are west to east by the sweep's key (§8). Straight child = the one whose far end has the smaller level (end_level), tie the west one. Hand of the other: -1 if it is west of the straight child, else +1. At a split: a diverging joiner leg with no crossings starts with its Corner (it must have that hand, else refused); any other diverging child starts with an SBend. At a merge: a non-straight child ends with an SBend into it.
- Crossings, per edge in order.edge_crossings: own bridge over x: Over(x) (both copies). Under x's doubled bridge: Under(x, copy), copy 0 first heading S, copy 1 first heading N (copy 0 is the north track). Under x's single bridge (a band crossing, F2): SBend then Under(x); hand +1 if this edge's S-side slot is west of (less than) x's, else -1.
- Refused (error text in the brief): a crossed In or Out row edge (Fable §2(3)); a row of another shape; a diverging joiner that crosses; a diverging Corner whose hand disagrees with its side; an edge between two rows.

**10.8 Band layers, settled for G1c(i-b) (orchestrator, 2026-11-12; F1, F3).** Between two rows, the left-to-right order of the vertical tracks at any height is the sweep's item list, so the band's y order is the sweep's event sequence, loosened to a partial order: an event (a node expansion, or a band crossing swap) must lie north of the last event that touched any item it touches. Layer = 1 + the largest layer of its touched items (items enter each band at layer 0; an expansion's children and both swapped items take the event's layer). Layer 1 is southmost. Events sharing a layer touch disjoint items and may share a y; (ii) spaces columns and gives each layer its height (bends, D113/D192 signal pieces, bays, F4 corners by rows). F1's band slot is then a band with events and b < R: its depth comes from its layers, inserted in (ii) between row b-1's south item and row b's north item; the stack itself is unchanged. Band R also holds the stub (D206, 2 tiles) below its layer 1.
- T band R: N split L1, S merge L1 (D115a: both switches on one row), swap (AS, NE) L2 (the traced D2 above row 11).
- LL_RR band R: N2 L1, N4 L2, N9 L1, swap (J_e trunk, X_e trunk) L2, N11 L3, N10 L2: X_e's crossing S-bend (L2) lies wholly above the J_w trunk's S-bend at N2 (L1), as F3 requires. Band 2: N3 L1.

## 11. G1c(ii): placement and render of the seed (orchestrator DRAFT, 2026-11-12; for Fable review)
Input: topology, paths, graph, order (rows, edge_crossings, band layers), structure (stack, bridges, turns), programs (§10.7), spec (CL, TL, prio_tiles p, nmax). Output: a JunctionLayout (tracks, bridges; no signals) whose traced template has the structure the programs say. **11.1 What must be exact and what may be loose** (RECON-G1c-seed §1-§2). The builder freezes the seed's size of rigid parts: bridges (heads and span), pieces under a bridge (on the head line), and every non-free link: an S-bend of 2 halves, any diagonal under a Y-axis bridge, a diagonal of fewer than 3 halves. Free parts (a straight X or Y run between points; a diagonal run of >= 3 halves not under a Y-axis bridge) may be any length: their constants cancel and Lo (G1c(iii)) tightens them. So: rigid things are placed at their rule size; free runs get a loose length G (generous, any value >= their rule minimum; G = 2·TL + p, a single constant) wherever no exact relation binds.

**11.2 Coordinates as a difference system.** Tile x east, y south. Variables: y of each stack item, of each band layer and of the box's S edge; x of each row node, lane split, lane merge, bridge head, and of each column segment (a maximal vertical run of one edge between two bends). Every relation is `v - u >= k`; the seed is the least solution from the NW corner (x = 0 at the W ports, y = 0 at the northmost item) by longest paths. Exact relations use equality as two inequalities.

**11.3 Y.**
- Stack items on consecutive rows (tracks of one lane triplet and of neighbouring triplets are adjacent, D142; a copy/approach to lane S-bend is 2 halves, rigid).
- A band b < R with layers sits between row b-1's south item and row b's north item; band R lies below the last item. Each layer gets height G (loose: bends, D113/D192 pieces, bays, F4 corners all fit; Lo tightens). Exception, exact: a layer holding a band crossing has height = the crossed S-bend's columns moved + 2·K_HEAD (K_HEAD = 1) + 2 (one plain piece beyond each head, D113), so the single Y-axis bridge spans exactly the S-bend.
- Band R: the layer-1 switches sit on one row (D115a), STUB = 2 tiles (D206) above the S edge.
- Corners: an exit Corner from lane row y spans k rows and k columns, k = (h - 1) / 2, h = the least odd number >= CL (curve rule). A joiner Corner onto approach row y_a starts k rows below y_a when it follows a Y run; a diverging joiner's Corner at its band split spans by rows (F4): k = y_split - y_a, columns the same.
- Port rows (W/E): the notation rows (D38/D142: one row per lane, one per "_") placed to minimise the largest fan S-bend over both sides, ties north; the fan S-bends of one side start at a common column (Fable §2(1)).

**11.4 X.**
- Column order: in every slice (each row's items, each band layer before and after its events) consecutive items satisfy x(next) - x(prev) >= 1. A straight child keeps its parent's segment; a diverging child is a new segment; a band crossing S-bend ends one segment and starts another.
- S port columns: the branch notation (e.g. L_R: columns c and c + 2) is exact on the bottom slice.
- Exit corners: x(column) = x(lane split) +/- k (heading E: +k). Joiner corners: x(approach run start) = x(column) +/- k.
- Row chain per lane, in travel order, loose (G) except where marked: port (box edge), fan zone (>= the largest fan S-bend's columns), exit split, lane split (doubled rows), near head, far head, lane merge, joiner merge (prio), fan zone, port. Loose gaps are G; the D148/D145 floors are left to the template.
- Bridges, exact: for a doubled bridge over crossers Z (all columns and diagonal halves of crossers on that row), copy 0's heads at min(Z) - 1 - s and max(Z) + 1 + s', copy 1 the same span shifted upstream by 1 (D118 stagger), both spans equal (D80) and the least that clears both rows' Z. A single bridge: heads one row beyond the crossed S-bend's rows.
- Box: all W ports at x = 0, all E ports at the largest x; S ports on the S edge.

Shared edges are drawn once; tiles are the union of tracks; bridges listed once per copy.

## 12. Signals as graph tokens (D211; orchestrator DRAFT, 2026-11-12)

**12.0 Order.** G1d (the checker reads ports and movements from a topology) first: it is the oracle for every step below and for LL_RR. Then ST1 (signal tokens and run rules), ST2 (the prio element), then the LL_RR signal findings, then the rig.

**12.1 What a signal token is.** A signal the graph places by rule, with a reason, like a bend or a bridge (D211: "the concept of gaps gets replaced by the concept of a signal"). Its rule names the event it serves on a route (a lane path and copy): a split, a merge, a bridge, an out port. Its exact piece is resolved on the rendered route, because a signal may stand on a bend's half piece (the old pass puts the T's lane-split signals on diagonals): the difference solve gives tiles to bends and heads, not to the pieces inside a bend. Placement's floors stay as they are and each now names the token it holds (the series gap holds SeriesGap, the stub holds Stub, keep_slot holds BeforeSplit / AfterMerge, D148's p + 1 holds the prio's coverage plus its post-split signal); a floor that holds no token is a finding. A token with no legal piece in its stretch is not placed (as the old pass); the checker judges whether that stretch needed one (G6, the D113 clause), so a missing room shows as a checker violation, not a silent pass.

**12.2 Anchor rules (ST1).** Legal piece: not on a bridge, not a head, not a switch tile, no overlapping track on its tile (IsLegalSignalPiece). Stretch: the pieces between two consecutive events of the route. Facing: along the route. Type: spec.signal_type.
- **BeforeSplit / BeforeMerge** (G6): the last legal piece of the stretch before the switch.
- **AfterSplit** (D192, D113, generalised to every split, not only line-choice splits): the first legal piece after the split. On copy 1 after a lane split with no legal piece before its head, none (the D110 form; G6 asks nothing there).
- **AfterMerge** (G6): the first legal piece after the merge.
- **BeforeBridge / AfterBridge** (G6, D113): the last legal piece before a near head, the first after a far head. Between two series bridges the one plain tile takes both (**SeriesGap**, D209).
- **Stub** (D206 open, D115a): on every out route, the piece before the boundary tile.
- Two tokens resolving to the same piece are one signal (D117a: one signal meets every rule of its stretch). No token is removed for redundancy here; the prio element (ST2) owns its coverage.

**12.3 Run rules (ST1).** After the anchors, on every route in path order:
- **Bays** (G7, D83, D88, D176 n = 1): on a path that is not a through movement, before every merge: from its BeforeMerge signal upstream, a signal on the first legal piece at least 2 TL units further, repeated until the upstream split; the leg must hold one whole bay (placement's floors give it; a shorter leg places no bay signals and the checker reports it, G7).
- **Fill** (G6 spacing, D97 drag): between consecutive signals of the route, PlaceDragSignals at sd (the first and last piece of a route never take one, which keeps the box edge free, G10).
- Shared edges give the same signals on every route through them (fill walks upstream from the downstream signal, which the routes share), so the union is drawn once.

**12.4 The prio element (ST2; D211 exception).** A prio is one element of the stack (the Prio item beside its lane, opposite the joiner, D75/D87): for each ML merge with a joiner of another movement, the element covers 2p units upstream of the merge plus one piece (D107), places the ML signals inside its coverage itself (replacing fill there), one join per ML block, the row track beside the lane, its Combo/Exit signals, and turns the joiner's BeforeMerge into an Entry signal (G9, G9b). Its geometry is PlacePrio's (junction_signal_pass.cpp:305-432) restated on the route, with the coverage pattern fixed by the element rather than read back from fill. Brief after ST1, from a short recon of PlacePrio, CheckPrio and CheckPrioReach on the T render (the old pass on the T render is clean but for one G9 violation at (21,4), wip/diag-T-render-oldpass.txt).

**12.5 Interface (ST1).** RenderJunctionTrackPlacement gains `const JunctionSpec &spec` and an out-parameter for the signal tokens: `struct JunctionTrackSignal { uint16_t path; uint8_t copy; JunctionSignalReason reason; TileIndexDiffC tile; Trackdir facing; }` (reason: BeforeSplit, AfterSplit, BeforeMerge, AfterMerge, BeforeBridge, AfterBridge, SeriesGap, Stub, Bay, Fill), and draws them into layout.signals. Events on a route come from SwitchEventsOf over the rendered layout (all its tracks are used) and its bridge pieces; nothing is traced by the checker.

**12.6 Tests.** ST1 outer: the T render's CheckSignals, CheckWaitingRoom and CheckDeadlock are empty (the old pass reaches that on the same render, so it is reachable), and Connectivity, Geometry, Bridges, Footprint stay empty; every token's reason is the one its rule gives on a few pinned pieces (the T's W series-free bridge: BeforeBridge, AfterBridge; the S stub). No layout is read. The recipe per field is RP2's recon (RECON-graph-input.md).

**13.2 Tags.** Every input piece carries its graph element: edge, token index (or "run between tokens"), copy; node pieces their node; bridge pieces their bridge. The template keeps them on its points, links and classes. Everything downstream speaks in graph elements.

**13.3 Rules on graph elements.**
- D212, the port edge: the run between a port and its Fan token is the line's approach. The class of the Fan token's first point leans toward the edge's node (in-edge: downstream; out-edge: the Fan's last point leans upstream toward the last node). Lean classes are snapped after all other classes, to the extreme toward the node that the propagation allows, so they move only as far as the other tracks and facts allow. A Fan that shares its class with the port does not lean.
- Signals: the template's paths keep their route identity (lane path, copy), so after a solve the routes are the template render's paths; the signal tokens (§12, incl. the prio element) are resolved on those routes. No tracing, no T pass.
- Prio rows and coverage from the graph's merges (as NP1's builder rules, by movement).

**13.4 Facts and failures.** Terrain facts enter as bounds and domains (DESIGN-nodes §2, FABLE §1.1-1.2, HF1 heights). A failure (HN1) names the fact (tile, kind) and, through the tags, the graph element it hit (edge and token or run, node, bridge).

**13.5 Repairs are graph edits, applied incrementally.** A repair kind maps a named failure to one edit (D198/D199: few children, ranked by cost; D197: at the cursor first):
- an S-bend on the failing edge's run that stays shifted (D182, D195);
- a ramp structure or a terraform overlay for a Height failure (D196; the terraform check is local, DESIGN-N3 §11);
- a crossing changed between bridge and tunnel, or main line over/under (D190);
- (later) a node moved to another edge, an order or doubling change.
An edit changes the graph, and from it the template entries of the edges it touches. The search does not rebuild or re-solve the whole template per child.

**13.5a WITHDRAWN** (FABLE-projection verdict; engineer agreed 2026-11-12, D214): depth-first with per-edge marks rested on a wrong premise (template build ~0.2 ms vs solve ~2 ms per state; the solve is global; class numbering is global). D198's best-first order stands; each state is rebuilt from its edit list (13.8).

**13.6 Warm start.** Per (spec, topology, orientation), keep the last solved state (its edits and positions). On the next hover, re-check its facts at the new spot first; search only when that fails, seeded with the same edits (FABLE §2 "warm start"; N4).

## 13.9 Structural repairs (orchestrator DRAFT, 2026-11-12; for the engineer's review before any brief)
**Why (P4b finding, engineer agreed it is a plan gap).** The seed is compact: LL_RR has one long free run outside prio coverage; most of its runs are 1-6 pieces. A local out-and-back detour (P4b) rarely fits, and Piece, Height and Occupancy failures, which a house in the core gives, have no repair. The repairs that matter change structure upstream of placement (DESIGN-nodes §2: "obstacles add structure to the map so it is always consistent"; D182, D190, D195).

**13.9.1 The edits (each a graph edit on the state's edit list, rebuilt from the structure stage: structure -> programs -> placement -> routes -> input -> template -> solve).**
- **Shift (stay shifted, D182/D195):** lane L, from the run before element X (the failing element's tag: an edge token, a node, a run) to side s (+1/-1): a new stack item (row) beside L's row on side s for the stretch; an SBend onto it in the run upstream of X; L stays on it through X and returns by an SBend in the first run downstream where its row is free again, or never (to its out port: the line leaves shifted, D182 "may not rejoin at all"). Placement treats the new SBends as ordinary tokens with D215 floors (next to the feature they serve).
- **Node move:** a split or merge node of L moved to the adjacent edge position along its lane (one edge earlier or later in travel), when the failure names the node's tile or its prio element (rows of the prio, coverage).
- **Crossing swap (D190, roots not children, §13.8 item 3):** for each crossing, bridge over vs under and bridge vs tunnel, enumerated as roots of the search.
- **Row added (depth):** the box grows one row on a side (D185a: depth is a solve variable); placement then re-solves rows.
- Local detour (P4b) stays as the cheapest edit where a run is long enough.

**13.9.2 Failure -> edit.** Straight/Break on a long run: detour (P4b), else Shift of that run's lane. Piece/Height on a class: per point tag in the class (its edge/token/run, its lane): Shift of that lane before the element, both sides; if the element is a node: Node move. Occupancy (two elements): Shift of either element's lane away from the other. Template errors after an edit: the child is dropped. Few children (D198/D199): one per (element, side, kind).

**13.9.3 What placement must accept (the undesigned part).** Today stack, programs and placement come from the topology by rule (G1b-G1c). An edit adds stack items and tokens that no rule produced. Needed: (a) a structure with "extra" stack items per edit (a Shift row: which edges' stretch it spans, its side); (b) programs that splice the edit's SBends into the lane's edges at the named runs; (c) placement's gap table applied to them as to any token (curve gaps, D215 next-to-feature floors, occupancy against neighbours). OPEN-13b: is a Shift row a new stack item between existing rows (rows renumber: the whole stack's Y solve redoes, cheap) or a row outside the box edge (box grows)? Recommendation: a new stack item; the Y solve already places items by order and gaps.

**13.9.4 Tests (outside-in).** LL_RR with a house on a core tile where no detour fits (e.g. P4a sweep's Piece and Height tiles: (40,8), (44,11)) builds by a Shift, checker clean, states gated; a house on a node tile builds by a Node move or a Shift; the T §0b cases (house beside the hub, hub tile, incline) keep building.

## 14. Placement on the terrain (orchestrator DRAFT, 2026-11-12, D216; for Fable's review, then the engineer's)
Rulings: D216 (projection = the graph's placement solved on the target terrain; no flat stage), D213 (graph is the source; layout output only), D201, D183 + FABLE-nodes-perf §1 (facts are bounds; monotone propagation, no branching on positions; failure-driven structure search; warm start), D193 (correct by construction), D194 (heights as facts), D196-D199 (repairs from named failures, few children, cost), D212/D215 (row changes next to their features), DESIGN-nodes §2-§3. Supersedes §13.1-§13.3 and parks §13.9.

**14.1 One solve.** Variables: the placement's points (node tiles, token spans, bridge heads, ports, stack rows; the `along`/`eq`/`ge` system of PlaceJunctionTrackGraph). Relations: the gap table as today (each a rule floor with its source; SF1b/CS1-style derived floors; TL1 makes every floor scale with tl/speed). Facts: the target terrain's per-tile facts (JunctionFacts: Fits, EdgeZ, Blocked). The flat layout is this solve on flat facts. The traced node template stays only as a test oracle and checker.

**14.2 Facts as monotone relations (FABLE-nodes-perf §1.1-1.2).** With the structure fixed (rows, token order, crossings):
- a straight run on row r between points a and b must be buildable on every tile between: `x_b <= next_bad_r(x_a)` (and its mirror for the other heading), next_bad nondecreasing, so the least solution exists and propagation finds it;
- a token's footprint (bend halves, switch tile, prio element, bridge head) is a rigid mask relative to its anchor: its legal anchor positions are a domain bitset (mask AND the fact rows);
- heights: a run is buildable only if consecutive tiles meet at equal edge heights (an interval property, the same monotone form); a bridge's heads must suit a ramp at equal z; spans <= max_bridge_middle;
- Y first, then X, as placement does today; the Y phase's fact-blindness (DESIGN-N3 §6) is measured, not assumed away.
What moves across from the node solve: JunctionFacts, JunctionPositions (propagation with trail and domains), the height checks; what is already in placement: prio element floors, the stack (occupancy by construction), the curve-gap floors.

**14.3 Preference.** Least positions along each heading as today, except each row change sits next to the feature it serves (D215) by exact relations where the rules allow (SF1b's pattern; port fans included), so no separate lean step.

**14.4 Failures and structure edits.** An infeasible propagation names its chain of relations and the fact at its end; the variables ARE graph elements, so the failure names them with no tags. Structure edits for every change the relations cannot absorb (DESIGN-nodes §2: obstacles and heights add structure so the map stays consistent): graph choices (node order, a crossing's over/under and bridge/tunnel, D190 roots, an added row, D185a); obstacles (an S-bend pair around, or staying shifted past, D182/D195); elevation (a ramp: a straight run forced where the line changes height, D194/D196; a bridge or tunnel inserted to cross a dip or ridge); terraform is a fact change (D196). Position effects (sliding, stretching, leaning) fall out of the relations and need no edit. Search: best-first by cost over edit lists (D198/D214; P4b's frame), each state = graph + edits, re-placed per state.

**14.5 Steps (each test-first).** T1: placement on JunctionPositions with no facts; oracle: the T and LL_RR placements equal today's. T2: blocked tiles as run bounds and footprint domains; outer: P4a's 20-tile sweep on LL_RR solves more tiles by relations alone, every result checker clean. T3: height facts; outer: the §0b incline and ridge cases. T4: failures as named relation chains; structure edits in the P4b search frame; outer: a core house on LL_RR builds by a row edit. T5: hover by topology with warm start and a topology picker; outer: hover p99 < 100 ms over a cursor sweep. T6: terraform and tunnel edits. The P1-P4b node path stays until T4 replaces it.

**14.6 Open for review.** (a) Is the "run buildable" relation exactly monotone with heights (foundations make a tile's fit depend on its tracks; runs are straight, so per row it is fixed)? (b) Bends on slopes: a bend's mask depends on the slope under each half piece; is a per-anchor domain enough? (c) Bridges: head z equality couples two positions; is it a domain on the pair? (d) What the Y phase must know about X facts to avoid fact-blind row choices. (e) Cost model for the search (D199 organic/artificial weight).
