## 1. Topology (pure; no coop rules, no geometry)
- **Line** = a physical track. **Route** = a train's path from an entry port line to an exit port line (or to one of several exit lines: a choice route). Routes share lines; lines share nothing.
- **Port** = one node per (side, direction) group: side W/E/N/S, an indicative compass heading (travel direction at the port), its lines in order (left to right across travel).
- **Edge** = an ordered vector of lines between two nodes; each line labelled with its route set. The vector never changes inside an edge.
- **Node** = where the vectors change. Behaviour derived from the labels: split (a line's routes divide), merge (lines join), crossing-free reorder is impossible (order changes only by crossings). Every split is 1 -> 2 and every merge 2 -> 1 (cascades are chains, order authored).
- **Notation** (engineer's): letters = routes, digit = lane; a line carrying several routes concatenates them (`CB1` = lane 1 carrying C and B). A node is written `in-vector -> out-vector`, e.g. `EF1, EF2 -> E1, E2, F1, F2`. A topology is authored as data (a pattern = a topology, or a generator writing one per lane count); a text file format holding ports (side, heading, lines), routes and nodes.
- **Derived:** crossings: two routes must cross iff their endpoints interleave around the boundary (port order clockwise); since D24/D285 forbid swapping by shared track, an interleaving pair crosses on some pair of their lines that are separate there. Where bundles interleave at their ends (`[C1 C2] + [B1 B2] -> [C1 B1 C2 B2]`), they fray into single-line edges first and single lines cross whole. The embedding (cyclic order at each node, line order in each edge) and each line's event order (nodes and crossings along it) follow; crossing order along a line is fixed where forced, else a declared choice.
- **Crossings are level relations**, not flow nodes (D307): A over B at a position in each line's event order.

## 2. Layout: octilinear integer program (the solver)
Reference: Nöllenburg & Wolff, "Drawing and labeling high-quality metro maps by mixed-integer programming" (2011): octilinear layout with fixed embedding as a MILP. Ours adds tracks' game rules. Through `JunctionMilp` (HiGHS) only.
- **Vertices:** per line, a chain of vertices: its start (port), every event (node it passes, crossing), and bend vertices between events (enough for its required turning plus one S-bend: the minimum 45-degree turns from heading in to heading out, plus 2 spare per inter-event stretch; spare bends may take length 0 = no bend). A node is one shared vertex of the lines it joins (a split's legs leave it within 45 degrees of the trunk, the diverging leg on its embedding side).
- **Segments:** between consecutive vertices, a direction in 8 (binaries, one chosen) and an integer length >= its floor; x/y differences = length times the direction's unit (big-M on the binaries). Consecutive segments differ by at most 45 degrees (no 90-degree corners: they cap speed at 61); a direction change is a curve, and consecutive curves keep `JunctionCurveGaps` (same hand `min(2TL-1, max(2,CL))`, opposite 2, non-consecutive `min(2TL-1,(j-i)CL)`, CL from `DeriveCurveSpacing`) as segment length floors in half-tile units (diagonal counts half per tile, as today).
- **Sides from the embedding:** lines of one edge run parallel at one line spacing in their vector order (exact for a bundle stretch; D287 parallelograms); for any two segments of different lines the embedding gives which side they pass, and non-overlap is "separated by >= 1 tile on that side" (`JunctionUnrelatedTileGap`, parallel diagonals may share a tile, `JunctionTracksMayShareTile`). Pairs are added lazily: solve, rasterise, detect clashes, add their separation (one of the Nöllenburg 8-sector separations, the sector picked by the embedding when it decides it, else a binary), resolve.
- **Crossings:** the two lines' crossing vertices coincide. A binary per crossing (per route pair when bundles cross whole) picks the over line (D307 choice): the over line's segment through the crossing is axis-aligned (bridges and tunnels are straight), straight for the bridge's head floors each side; the under line is not parallel to it there. Bridge over bridge forbidden; tunnel under tunnel forbidden; tunnels allowed only when the spec allows. Ramp/head lengths from the existing bridge rules (`table/bridge_land.h`, the head floors placement uses today).
- **Doubling (D309):** a crossing where the over line carries a main route is realised doubled when the policy says so: the line splits into two copies before the crossing, both cross (adjacent decks, the stagger of D287), rejoin after; equal curve counts and lengths (equal pathfinder cost). In the program the copies are two parallel chains between a split vertex and a merge vertex created by the layout, not the topology.
- **Policy floors (rulebook, tagged game/policy, hard/soft):** prio coverage before a merge on the main line (`JunctionPrioTiles`), signal spacing, straight runs after splits and before merges (today's constants in `junction_spec`), splits before merges. Soft: main lines stay at ground level (cost), fewer bridges, compactness.
- **Objective:** flat build cost (track tiles, bridge spans, as `junction_joint` prices) plus compactness; a tie break keeps results deterministic (one thread, zero gap, fixed seed, as `JunctionMilp` already does).
- **Search order:** inside first is the branching priority (crossing binaries of the core before ring ones); HiGHS does the search; learned conflicts are HiGHS's business.

## 2a. Formulation (for review; the solver is not written yet)

**Frame and lattice.** Canonical frame (x east, y south, branch on S; the T is the drawing turned half a turn, because the checker has no N edge). Coordinates are integers in half-tile units: tile (x, y) covers [2x, 2x+2] x [2y, 2y+2]. A track vertex is a tile-edge midpoint, so X + Y is odd; an axis piece moves 2 units, a half piece 1 unit on each axis. A segment's length u is its Chebyshev length in these units, which is exactly the curve-gap unit (axis tile 2, half piece 1).

**Variables.**
- Box: W, H (tiles), 0 <= W, H <= S, S the hover snapshot extent (the seed uses the window's snapshot size).
- Per vertex v: X_v, Y_v in [0, 2S]. Track vertices (port, node, bend) also: integer m_v with X_v + Y_v = 2 m_v + 1, binary p_v and integer h_v with X_v = 2 h_v + p_v (p_v = 1: X odd, v is the midpoint of a tile's north or south edge, where N/S pieces end; p_v = 0: a west or east edge, where E/W pieces end). Crossing vertices carry no parity rows (a perpendicular crossing sits at a tile centre).
- Per segment s (consecutive vertices of a chain): direction binaries d_{s,k}, k in 0..7 (N, NE, ..., NW), sum = 1; per-direction lengths w_{s,k} in [0, 2S], w_{s,k} <= 2S d_{s,k}; u_s = sum_k w_{s,k}; binary z_s (s has length >= 1).
- Per bend vertex v: binaries tL_v, tR_v (a left / right 45-degree curve at v); T_v = tL_v + tR_v.
- Per crossing c: binary o_c (1: the lower-indexed line is over, D307).
- Per doubling group g (below): binary a_g (the group is doubled).
- Per lazily added separation with no side from the embedding: 8 sector binaries, sum = 1.

**Chains.** Each line is one chain of vertices: its start (port vertex or node vertex), then per stretch between consecutive events (start, each crossing in event order, end) the bend vertices, then the event. A node is one vertex shared by its three lines. A crossing vertex is shared by its two lines (the same X, Y variables).

**Spare bends.** Each stretch gets r_l + 2 bend vertices, r_l the line's least 45-degree turn count (from the heading of its route's entry port to that of its exit port, first path; 0 for a straight line): the turns may fall in any stretch, and 2 spare give one S-bend per stretch (DESIGN-planar §2). A bend vertex with no curve is a plain point on a straight. This is the plainest count; it is the first thing to cut if the seed exceeds 5 s (D297), recorded as a toggle candidate.

**Constraint families.** (rule or decision in brackets)
1. Displacement: X_{v+1} - X_v = sum_k ex_k w_{s,k}, Y likewise, (ex_k, ey_k) the unit of direction k. Exact, no big-M on coordinates.
2. Parity: an E/W segment's end vertices have p_v = 0 (p_v <= 1 - d_{s,E} - d_{s,W}); an N/S segment's have p_v = 1 (p_v >= d_{s,N} + d_{s,S}). Diagonals free. [OpenTTD track geometry: an axis piece runs between opposite edge midpoints]
3. No 90-degree corner: for consecutive segments s, s' of a chain, and across a node from trunk to each leg, d_{s',k} <= d_{s,k-1} + d_{s,k} + d_{s,k+1}. [90-degree bend caps at 61, CLAUDE game rules]
4. Curve detection: tL_v = sum_k e^L_{v,k}, e^L_{v,k} <= d_{s,k}, e^L_{v,k} <= d_{s',k-1}, e^L_{v,k} >= d_{s,k} + d_{s',k-1} - 1; tR likewise with k+1.
5. Zero length inherits direction: |d_{s',k} - d_{s,k}| <= z_{s'}; u_{s'} <= 2S z_{s'}. A zero-length segment is no bend, never a hidden 90-degree corner.
6. Consecutive curves (JunctionCurveGaps, D-curve rules; CL from DeriveCurveSpacing): for bend vertices a < b on one route path, D_ab = sum of u between them: D_ab >= G1 (tH_a + tH_b - 1) - G1 sum_{a<c<b} T_c for each hand H (same hand, G1 = min(2TL-1, max(2, CL))); D_ab >= 2 (tH_a + tH'_b - 1) - 2 sum T_c (opposite hands). Pairs only within a 2TL window of the vertices' least possible distance.
7. Non-consecutive curves: lazy. After a solve, JunctionCurveGaps on each route path's solved hands; a violated pair (i, j) adds D_ab >= g_ij (sum_{c in C} T_c - |C| + 1), C the solved curves from a to b. Valid: more curves between only raises the true floor.
8. Ports: a port line's first (or last) segment has the port heading fixed and u >= 4 (the boundary tile and the signal tile before it: signals Stub; the footprint ends one tile beyond the outermost signal). Port vertices lie on their side: X = 0 (W), X = 2W (E), Y = 2H (S); along the side in ring order, lines of one port 2 (gap + 1) apart (ml_gap or branch_gap, the notation), two ports of one line (its two directions) likewise, ports of different lines at least the unrelated gap (family 13).
9. Box: every vertex inside [0, 2W] x [0, 2H] (footprint, D300).
10. Node geometry (split; a merge mirrored): the vertex V is where the trunk's last piece ends; each leg's first segment is within 45 degrees of the trunk's direction (family 3) and the two legs differ: with directions relative to the trunk, (left leg, right leg) in {(-45, 0), (0, +45), (-45, +45)} (left/right from the authored leg order, the embedding). The split tile is the tile both legs' first pieces stand on. Each leg's first stretch has u >= 2 before its next event, so a signal-legal piece (a tile with no other track) follows the split [signals AfterSplit, BeforeMerge].
11. Crossing c of lines a and b at shared vertex C: both lines straight through C (their two segments at C have equal d). Over line (o_c picks it): its direction at C is axis (sum of diagonal d <= 1 - o_c for line a, <= o_c for b); under line not parallel to it (d_{a,k} + d_{b,k} + d_{b,k+4} <= 1). Head floors on the over line's two segments at C: u >= 3 when the under line is perpendicular (C is a tile centre; the deck's middle is C's tile, the near head's outer edge 3 units away), u >= 4 when diagonal (its two half pieces on the deck row stand in the tiles either side of C) [bridge rules, table/bridge_land.h; CheckBridges]; written u >= 3 + (diagonal binaries of the under line) - 4(1 - o_c) per side. Under line's segments at C: u >= 1. Deck middles are then 1 or 2 tiles; bridge_span_ok must accept them, else the spec is refused.
12. Consecutive crossings on one line l (c1 then c2): both over on l and no curve between: one merged deck, H(c1, back) + D + H(c2, front) - 4 <= 2 max_bridge_middle. Both over with a curve between: D >= H(c1, front) + H(c2, back) + 2 (a signal-legal tile between bridges: every bridge is its own block). l under at one and over at the other: D >= H(over side) + 1, so l's deck never spans the tile where another deck passes over l [no bridge over a bridge, D307]. Each written with big-M on o and T.
13. Clash separation (lazy): see below.
14. Prio coverage (D301; JunctionPrioTiles, rounded even as the signal pass builds it): at a merge where a prio route's line meets another, the prio line's last stretch into the merge is axis and straight for n_prio + 1 tiles (u >= 2 n_prio + 2 with no curve), and the tiles the prio element draws beside it (the joiner's side) are kept clear by family 13 treating them as occupied.
15. Waiting room: a non-prio route's run from its last split (or port) to a merge is at least TL tiles (2 TL units) [signals: bays of 2 TL units].
16. Splits before merges (D24) are topological: the authored topology is checked, not the layout.
17. Doubling (below).
18. Terrain (lazy, §3): below.

**Lazy clash separation.** Solve; rasterise every line and copy; for each tile, pieces of two lines that are not the same line, not two legs of one node on its split tile, and not an under line beneath a deck, clash when JunctionTracksMayShareTile refuses them, and two pieces in adjacent tiles clash when JunctionUnrelatedTileGap says they must be 2 apart. For each clashing segment pair (s, t) add: for a separation axis phi in {x, y, x+y, x-y} and a sign, phi(each end of s) + g <= phi(each end of t), g the least centre-line distance at which pieces of these two directions are allowed (a table over direction pairs built once from those two functions, not a constant). When the embedding fixes the side (two lines of one edge, two legs of one node, a line and the crossing it does not take part in at a shared vertex), that sector is used; otherwise the 8 sectors take binaries (big-M 4S). Resolve until no clash; the rows stay for later solves of the same (topology, spec).

**Doubling (D309, D80/D188, D299).** A doubling group g is a maximal run of consecutive crossings along a line l that carries a prio route (the fixed route, D301; choice legs are never doubled, D299). Its chain holds a second copy between a copy split vertex S_g before the run and a copy merge vertex R_g after it, the copy crossing each under line of the run at its own crossing vertex (the under line's chain gets one more crossing vertex per copy, ordered by the copy's side). a_g >= o_c for every crossing of the run where l is over (hard policy). When a_g = 0 the copy coincides with l (equal coordinates, its segments and the extra crossing vertices collapse to length 0) and is not rendered. When a_g = 1: the copy is l's neighbour at one line spacing on its outward side, both copies cross whole in the same order (adjacent decks, the stagger falls out of the head floors against a diagonal under line: D287 parallelograms), equal pathfinder cost: equal axis length, equal diagonal length and equal curve count on the two copies (YAPF ties); the split and merge obey family 10; the rejoin is recognised by the checker's D302 test (both incoming tracks carry the same lane paths).

**Big-M values.** Lengths and coordinates are bounded by the box bound S (the snapshot extent the plan must fit in), so every big-M on a length is 2S, on a sector separation 4S (sum of two coordinate ranges), on a floor at most the floor itself (families 6, 11). No other constants.

**Objective.** Flat build cost as the game prices it: rail_piece/2 per axis unit, rail_piece per diagonal unit (one half piece), each deck at prices.bridge(middle) less the track it replaces, doubled decks twice; plus compactness W + H at one rail piece per tile; plus a soft cost per crossing where a prio line is over (main lines stay at ground level). No tie-break weights: JunctionMilp is deterministic (one thread, zero gap, fixed seed).

**Terrain and hover (§3).** Terrain facts are checked on the rasterised result: a run tile failing JunctionFacts::Fits for its bits, a deck middle failing Spannable, a head failing Straight; each adds a separation of that segment from that tile (family 13 with the tile as a fixed obstacle), the sector chosen from the current geometry (the side the segment already lies on) so hover adds no binary. Hover: the seed's binaries (d, t, o, a, sectors) fixed by bounds, positions and lengths re-solved at the cursor.

**Route conversion.** Per route path and per copy (copy k of every doubled run it passes): the start piece is the first step from the port vertex (tile floor((2X + dX) / 4), floor((2Y + dY) / 4); trackdir from the axis: E X_SW, S Y_SE, W X_NE, N Y_NW); then every unit step (an axis step is 2 units = one piece, a diagonal step 1 unit = one half piece) gives F, L or R against the previous step's direction; at a deck the steps from the near head to the far head become B<middle>. RasterizeJunctionRoute renders it; the end tile and trackdir are checked against the chain's end vertex. JunctionTrackRoute: path = the route-path index, copy = k, one tag per piece (edge = line index, copy = k, token = RUN, run = 0).

**Reused functions and what they take.**
- JunctionMilp: AddVariable, AddRow, Solve, Value. It has no warm start and no branching priority: §3's warm start and §2's "inside first" priority need a seam added to JunctionMilp (a junction file, not upstream) or are dropped.
- RasterizeJunctionRoute(JunctionRoute), AddRasterToLayout: route moves only.
- JunctionCurveGaps(hands, tl, curve_speed, reference_speed), DeriveCurveSpacing: hands only.
- JunctionTracksMayShareTile, JunctionUnrelatedTileGap: TrackBits only.
- JunctionFacts(terrain) and its test terrain: tile queries only.
- SolveJunctionLevels(terrain, facts, offset, ramp_levels, tl, node tiles, port tiles, layout, routes, prio_beside, ...): no old types, but it reads each route piece's tag (edge, copy) as a label; the planar routes fill them as above.
- JunctionPrioTiles(spec); EstimateJunction / MakeJunctionBuildSteps (layout only).
- **SignalJunctionTrackRoutes needs old types**: JunctionTrackGraph (edges' to-node, nodes' split flag, path_edges), JunctionTrackPrograms (copies and SBend LaneSplit/LaneMerge roles), a JunctionTopology with lane paths, and optionally JunctionPrioSpan from a placement. Not adapted; decision needed.
- **CheckJunctionRules needs a JunctionTopology** (groups, movements, lane_paths with prio flags, D301): a topology-level type, convertible from a planar topology without loss, but it is an old type. Decision needed.
- **PlanJunctionHoverNear takes a JunctionGraphSeed** (old): the window's setting switch would call a planar hover entry of the same shape instead.

**Left out of the first build (review).** Tunnels: crossings are bridges only (the spec's tunnel prices may be unset; D155 tunnels are a later choice on o_c). Bridge type and span are the game's rules through bridge_span_ok and prices.

**As built (2026-11-15): corrections and choices, with evidence.**
- *Inside-first branching priority dropped*: HiGHS has no per-variable priority; a warm start (`JunctionMilp::SetStart`, HiGHS `setSolution`) is the only seam added.
- *Port spacing (family 8), reading fixed*: a port's lines are adjacent (2 units, the notation's "tracks of one direction are adjacent"); the gap 2 (gap + 1) is between the two ports of one side. The text above put the gap between a port's own lines.
- *Approach floor (family 11)*: the over line's segment into C is 2 units longer than the head floor (one axis piece before the near head), unless the deck merges from the crossing before: `RasterizeJunctionRoute`'s B starts from an axis piece (or closes an S-bend), so a head right after a same-hand curve does not render.
- *Merged decks (family 12)*: one binary per pair of consecutive crossings on a line (merged only when the line is over at both and no curve lies between).
- *Zero-length segments (family 5)*: u >= z added, so z = 1 means a real piece (otherwise a "length >= 1" segment of length 0 hides a turn); segments at a node, port or crossing vertex have u >= 1.
- *Canonical spare bends*: a bend vertex with no curve starts a zero-length segment unless the next vertex is an event (no layout is lost; removes the symmetry of where a straight is cut).
- *Family 6 lazy, like family 7*: written explicitly for pairs within seven turn points, round 0 of the T at one lane took 72 s against 20 s lazy; the rows are the same, added when violated.
- *Prio element room (family 14)* uses the tile rule: the signal pass needs the element's row tiles free of track (`SignalJunctionTrackRoutes` phase 0), not the touch rule.
- *Toggle candidates taken to meet time*: one spare bend per stretch instead of two (the cut §2a names first; two spare: round 0 of the T at one lane 21 s, one spare 11 s); heading windows (a line's segments keep to its routes' short turn arc plus one heading beyond each end).
- *Not built*: doubling (D309); a crossing that needs a main line over is refused, and a prio line is never over. Tunnels (as decided).
- *Measured, not met (D297)*: the zero-gap program on the T at one lane (1428 variables, 528 binaries) takes 11 to 71 s per lazy round and has not settled in 10 rounds (curve gaps keep reappearing as curves move between bend vertices); the seed budget is 5 s. No layout has been rendered yet, so the back end (render, signals, levels, checker) is wired but not exercised end to end.

## 3. Flat seed, terrain and hover
- The seed: the MILP on flat ground, cached per (topology, spec), budget < 5 s (D297).
- On terrain: the same model with the seed's binaries as the warm start; terrain facts as lazy constraints (a run over an unbuildable tile, a span too low, a head on a bad slope: add the separation/bound and resolve). Hover: the seed's binaries fixed, positions solved on the terrain at the cursor (an integer program with no free binaries: fast); budget < 100 ms, measured from the first in-game run (benchmark like the ridge bench).

## 4. Output and the reused back end
- Each line (and each doubled copy) becomes a `JunctionTrackRoute` (start tile, trackdir, half-piece moves: straight, 45-degree turns, bridge, tunnel), rasterised by `RasterizeJunctionRoute` into the `JunctionLayout`.
- Levels: `SolveTileLevels` and the level solve on the rendered routes, unchanged. Signals: `SignalJunctionTrackRoutes`, prio element from the routes' prio flags (D301 semantics: the fixed route holds prio). Pricing and build: unchanged. Checker: `CheckJunctionRules` on the result (its D302 rejoin test also recognises a doubled crossing's rejoin).
- In game: a client setting (openttd.cfg only; no savegame change) switches the junction tool to the planar model; the window's hub types map to authored topologies (T first, then LL^2 any = the PSG 227 pattern).
