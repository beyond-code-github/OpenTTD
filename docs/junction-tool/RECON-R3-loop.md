## 1. The fixed path's sequence when recording
`RecordJunctionPlacementSystem` (2645) calls `PlaceTrackGraph(..., &choices, error=nullptr, {}, {}, facts=nullptr, offset {0,0}, heights=true, classes_only=false, shared=null, make_shared=null, record=null, system=&system, sizes=null)`.
So `facts` is NULL (flat ground; fact_cons empty, no MaxX bound), floors on, `shared` null so plan_clearance runs, `sizes` null so X sizes come from `measure(true)`.
Order (fixed branch, 2326-2372):
1. Set `el.m` of free bends from `choices.m` (max(1,.) for S-bends, as is for fans), `rows_known = true`; box check on `port_offset + notation` (a failure returns empty, nothing recorded).
2. `plan_clearance(fixed->port_offset)` (2266-2316): (a) Y: refresh(false, measure(false)), `build()` with floors_off/relations_only/skip_clearance, then `flat_solve(flat_y)` (1157; plain longest path, no D215); (b) if ok: `vy=flat_y`, `set_port_rows`, refresh(true, measure(true)), `build()` + `flat_solve(flat_x)`; (c) if ok: for every X-axis bridge line and head whose flat X lies strictly inside, push `clear_y` (side from flat_y; side 0 gives both). Reads: chains, choices, flat Y/X. Feeds: `clear_y` only, used by the real Y build (1823). Any failure (build false or flat_solve false) is a silent `return` with `clear_y` EMPTY: no error, no log. Everything is restored (vx, vy, port_row, fan_m).
3. Y phase: refresh(false, measure(false)); `build()` (full, with `clear_y` -> "bridge middle clearance" Y rows); `solve(vy)` (486). `solve` calls `record_system()` FIRST (line 487) and then solves: so a Y system whose solve fails is still recorded (all its static rows + clear_y rows). A `build()` false (build_why, or occupancy_failed) returns BEFORE the record: nothing recorded.
4. `set_port_rows(port_offset)` (offsets from the choices, not best_offset); fan_m from vy.
5. X phase: refresh(true, measure(true)); `build()` (X): static rows, then, if `rows_known && !relations_only`: `compute_node_tracks()`, `flat_solve(flat)` INSIDE build (1907-1912, the "build()'s internal flat X solve"). Only if it succeeds: `add_occupancy(flat,false)` (can return false -> build false), `hug_heads(flat)`, `add_clearance_x(flat)`. If it FAILS the three lazy families are silently skipped and build continues. Then `solve(vx)` (2365): `record_system()` first, then the real solve (relations + D215 "next to feature" push, 502-545). A solve failure still leaves the X system recorded.
6. No re-solve in the record path. After the X solve, (rounds mode only) 2372+ is the other branch; fixed path continues to legality `add_occupancy(vx,true)` (2427, not reached/recorded) and result assembly.
What the record holds (`record_system` 406-484 + merge 469-485): `recorded[phase]` for each phase that reached `solve`; `*system` = X system fields if X recorded else Y; bends from X if `rows_known` else Y; relations = Y rows then X rows (both axes). Routes and `clashes` (the occupancy clash rows for the joint) are taken ONLY from phase 0 (`if (phase == 0)`, 421): no X record, no clashes.
Partial returns, by failure point:
- plan_clearance Y or X flat fails: record is complete except Y "bridge middle clearance" rows (clear_y empty).
- X build()'s internal flat_solve fails: X recorded with static rows only; NO occupancy, NO lazy hug, NO X clearance, NO clashes recorded as lazy ones (note `clashes` from add_occupancy never filled).
- Y `build()` false: empty system (test says "the fixed path recorded nothing").
- Y `solve` fails (positive cycle): record has Y only (X never built): relations = Y rows only; `routes`, `clashes` empty; pt_count/paths/chains present.
- X `build()` false (add_occupancy false or build_why): Y recorded alone, as above.

## 3. Pieces of the canonical point today
- "Y for the least rows, then X least plus the D215 push, at fixed lengths": the fixed branch itself (2326-2372) does exactly this: Y = `solve(vy)` (486; `positions.Lo` = least longest-path solution of the Y difference system, plus `clear_y` rows from plan_clearance), X = `solve(vx)` (same function; D215 push at 502-545 only `phase == 0 && rows_known`). Inputs: `JunctionPlacementChoices` (m per edge/token, corner span per token, port_offset), flat facts null or given; Output: `JunctionTrackPlacement` (nodes, ports, item_rows, `columns`=vx) and, through `system`, the recording; the point itself is not exposed except as `result.columns` (X per point) and `item_rows`/`nodes`/`ports` (rows only through those, no full vy per point).
- No function takes a joint solution (x, y) and re-derives least Y then X. What it would need: a `solve`-with-given-lengths that does not run plan_clearance or `flat_solve` for detection, and an output of vy/vx per point. Today the lengths enter only as `el.m` set from `choices` (2326-2330) and the Y phase's `refresh(false, measure(false))`; joiner_div Corner spans ARE inputs: `fixed->corner[e][tok]` is an eq row in the Y build (1679) and sets the Corner raster size kp (1683); `refresh` for the Corner's offs reads `vy` differences (650-651), so the X rasters follow the solved Y rows. `sizes` (2362) supplies X-phase bend sizes only.
- `port_offset`: taken from choices (2347); `best_offset()` (2239) only when not fixed.
- Point ids: `new_pt()` is called only at 192-196, 269-280, 725-762, all in the constructive pass from graph/programs/structure, before any choices are read (m applied at 2326). So ids depend only on chains. Evidence: pt_count and bend count equal over every round of every hub (L_R x LL_RR 89/27 x4 rounds, L_R x L_RR 72/20 x4, L_R x L_R 53/14 x2) although the relation counts differ (232..465, 588..620). ## 4. `SolveJunctionJoint` result (junction_joint.cpp 176, struct junction_joint.h 22-29)
- `x`, `y`: per system point (index = point id, size `system.pt_count`), the MILP optimum's columns and rows (lround of `milp.Value`, lines 376-379), x[0]=y[0]=0 by origin rows. Also `length` per system bend, and `choices` (m for "free" copy-0 bends, `corner` for "corner_rows", `port_offset` copied from the system, NOT solved).
- It is an arbitrary optimal vertex, not the canonical point (F2): rows and columns are not the least ones.
- Handing it straight to the fixed path as a point: no path accepts a point. `PlaceTrackGraph` takes choices (lengths) and recomputes vy/vx. The joint's y per point could in principle be handed as `vy` (it is feasible for the Y rows), but the fixed branch has no such input, and "keep L, t, port offset, sigma; resolve Y least; X least plus D215" means feeding `joint.choices` back into the fixed branch, which is what the test's `choices = joint.choices` already does. Missing for R3: (a) per-bend sizes for the Y-phase rasters and the horizontal S-bends (measured from rows today), (b) exposing the full vy/vx per point to detection, (c) lazy-row detection that does not depend on `flat_solve(flat)` succeeding (the failure mode in 1 and 2), and (d) t and sigma inputs (not in `JunctionPlacementChoices` today).
