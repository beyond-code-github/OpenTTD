## Summary
Graph-built JunctionNodeInput gives an EMPTY DiffJunctionNodeTemplates against the traced template for the T and LL_RR (diag; points 62 and 170), against both the trace of the track-only render and the trace of the signalled layout (those two traces are equal to each other, diag). Conditions: path order = the predicted order (Q1), events from nodes (Q4), bridges in route-appearance order (Q6), slots by the geometric rule (Q5). `input.used` is never read by the builder (N has no `input.used` use; only SwitchEventsOf's trace needs it).

## Q1 Path order and identity
- Order: TraceAllPaths (R:330-337) walks `ctx.ports` in order, In slots only (IsInSlot R:146); ports come from FindJunctionPorts (R:206-236): edge W, then E, then S (R:232-234), ascending along each edge, E side's slots reversed (R:220). Within one in port the DFS (TraceFrom R:264, `for (Trackdir td : candidates)` R:318) visits branches in ascending Trackdir enum order, so paths of one port are in lexicographic order of their trackdir sequences.
- Computable from graph data alone: key = (side W<E<S, coordinate of placement.ports[from_slot] along the edge (y for W/E, x for S), trackdir sequence of the route's pieces). Diag: this key reproduces the checker order at 7/7 (T) and 15/15 (LL_RR) positions. The doubled copies sort by the same key (copy 0 before/after copy 1 follows from the first diverging trackdir; LL_RR (1,1) before (1,0), so it is NOT "copy 0 first"). The route order out of RenderJunctionTrackPlacement is (lane path, copy), which differs from the checker order (diag listing: e.g. T checker 0 = lane path 1, LL_RR checker 0 = lane path 4), so a sort is required.
- Roles/slots: the ctx.paths entry is `{from_role, port.role, pieces, from, port.slot, lane.movement}` (R:278). from_slot/to_slot are JunctionPortSlots indices = JunctionLanePath.from/to exactly (T:25, ExpandJunctionLanes T:44); movement = the lane path's movement (lane found by (from,to), R:276). The role is the T's `TRoleOfSlot` (R:115, file-static; slot 0 EIn, 1 WOut, 2 NIn, 3 SOut, 4 WIn, 5 EOut) on the T, else `JunctionPortRole::EIn` for every port (R:230). No exported slot-to-role function exists; a 6-entry table reproduces it. The builder copies from/to into tpl.paths (N:176) and DiffJunctionNodeTemplates compares them; NodeAnchorShift reads EIn->SOut (N:1696), so roles are T-only.
- through/exit: IsThroughPath/IsExitPath (R:151-163) read only `topology.movements[path.movement]` groups' `main` flags: already graph data.

## Q3 used
UsedTracks (R:399-405) = tracks of every non-bridge piece of every checker path; bridge pieces are skipped (R:392, UsedTrackdirs), signals and prio-element tracks are not included (prio tracks are on no path). Diag: UsedTracks(render) == union of routes' non-bridge piece tracks == the render layout's track map; UsedTracks(signalled) == UsedTracks(render) (the 46/92 prio-element tiles added by the token pass are in layout.tracks only). So `used` is the route union, and the prio element's tracks are exactly what the layout has beyond it. The builder never reads `used`; its only reader is SwitchEventsOf's merge test (R:422-425, "another track used by some path"). In a graph pipeline `used` is dropped (D214 item 4) and the merge test is replaced by nodes (Q4).

## Q4 events
SwitchEventsOf (R:408-433) reads, per consecutive piece pair (cur, next): a split (true, k+1) when >1 trackdir of the next tile's layout tracks is reachable from cur (R:415-418); a merge (false, k) when another used track on cur's tile leaves the same edge and reaches next (R:419-427); bridge pieces never; sorted by index.
Graph rule (diag, exact): for each node n of the route's lane path (edges' `to.node` in graph.path_edges), the route's first non-bridge piece on placement.nodes[n] gives (graph.nodes[n].split, that piece index); for a doubled leg (structure bridge `doubled`), add (split, piece on placement.copies[e][t].first) for the SBend token t of programs.copies[e], and (merge, piece on placement.edges[e][t].second) for the SBend token of programs.edges[e] (placement T:1593; Q13). Diag: 0 mismatches on every path against the checker's events on the render, and signalled-layout events == render events (the prio element's tracks add none).

## Q5 slots
Checker slot per piece = IsLegalSignalPiece || IsSignalledPiece (N:686). Legal (R:788-793): not on_bridge, tile is not a bridge head (FindBridgeByHead), `!TracksOverlap(TracksAt(layout, tile))`, no signal on that track in either direction; signalled (R:783): a signal facing the piece's trackdir. The builder additionally drops event pieces (N:489-493); it does not drop the first/last piece.
Graph rule (diag, 0 diffs over 255 T and 886 LL_RR pieces): `geom = !on_bridge && tile not a head of any placement.bridges entry (both copies, skip the {0,0}-{0,0} copy-1 of a single bridge) && !TracksOverlap(union of all routes' non-bridge piece tracks on the tile [+ prio-element tracks])`. With no signals yet, slot = geom. With signals/prio, slot = (geom && no token signal on the track) || a token signal facing the piece's trackdir (tokens from SignalJunctionTrackRoutes). The anchor rule ok(i) of the token pass (T:1963-1969) is the same plus `0 < i < n-1` and not an event piece; reusable as is once its layout reads are replaced (Q9).
Diag: the render-layout slots and the signalled-layout slots differ at 21 (T) / 49 (LL_RR) pieces, but the two TEMPLATES are equal (diag): slots only matter as keep_slot/add_room facts, so the input may use geom-only slots (no signals needed before the solve). Prio-element track tiles in the "with prio" variant were taken from layout diff in the diag; their derivation from the graph is ST2's element geometry (INFERRED).

## Q6 bridges
layout.bridges (rasterizer: start/end swapped so x+y ascends, junction_route.cpp:142; AddRasterToLayout dedups, :172-175) vs placement.bridges (T:1660: per structure bridge {copy 0, copy 1}, start = head the carrier reaches first, a single bridge's copy 1 = zeros). Diag: equal as SETS for both (T 3, LL_RR 13; JunctionBridge.z = 0 and tunnel = false everywhere). ORDER differs for LL_RR (placement: structure order, copy 0 then 1 per bridge; layout: first appearance walking routes in (lane path, copy) order); T equal. The builder keeps input order in tpl.bridges (N:323-340) and DiffJunctionNodeTemplates compares it: build `bridges` from the routes' bridge runs, normalised, deduped, in route order (diag: equals layout.bridges for both topologies). z does not exist for bridges (tunnel floor only).

## Q7 Tags (RenderJunctionTrackPlacement, T:1665-1796)
Known lines: copy c = `for (int c ...)` T:1695 (copy-1 tokens chosen at T:1713 `copy1`); edge e = `for (uint32_t e : edges)` T:1712; token t = `for (size_t t ...)` T:1717 (token = tokens[t], span = spans[t], T:1714-1719). The loop appends MOVES, not pieces: pieces exist only after `RasterizeJunctionRoute(route)` (T:1789). Tagging recipe: record `route.moves.size()` at four places and convert offsets to piece indices (F/L/R = 1 piece; `B<m>` = m+2 pieces): the run before a bend is the F append T:1772 (tag "run before token t of edge e"), the bend's moves T:1773 (tag (e, t)), the Over's run T:1733 and its `B` T:1736 (tag the bridge pieces (e, t, bridge b)), the final tail T:1787 (run to the out port). Under tokens emit nothing (T:1720): their pieces are inside the surrounding F run and are tagged by tile range placement.edges[e][t] (span.first..span.last). A Fan with no off-line run is skipped (T:1742-1746): no pieces, tag none. Caveats: (a) D110 pops the last L/R (T:1729) and the bridge's near head replaces the closing piece, so tag that piece as the bridge's; (b) shared edges are re-emitted by every route through them, so the tag is per (edge, token, copy) and equal across routes (dedup by piece identity (tile, trackdir), N:148-165, keeps the first tag). Cheaper alternative: tag after the fact by tile range from placement spans (no change to the render), but the move-offset route is exact.

## Q14 Anchor
tpl.anchor / anchor_y (N:713-722) = the X class of the last point and the Y class of the first point of the first `exit` path (T: EIn->SOut); AddJunctionNodeConstraints pins both classes at their flat values (N:727-733), so the template frame keeps that translation fixed and the solve's output is relative to it. NodeAnchorShift (N:1694-1703; called N:1719, :1745) recovers the normalisation shift of the rendered (Normalise'd) layout by tracing the layout, finding the EIn->SOut path (T-only: MakeJunctionCheckContext, TRoleOfSlot) and comparing its end pieces' tiles with the template's flat tiles; SearchJunctionNodes then forms `layout_offset = state.offset - shift` (N:1747) and GenerateJunctionNear starts from `frame.hub_x - topo.hub.x, -topo.hub.y` (junction_game.cpp:459, hub = JunctionNodeTopologyT's, T-only; its definition INFERRED, not read).
Placement port slots give the same reference: diag, the first exit path's front/back piece equals placement.ports[from_slot]/[to_slot] (T (0,1)/(28,13); LL_RR (0,4)/(37,24)). So anchor = the class of the point at ports[exit.to] (x) and ports[exit.from] (y) for the first exit lane path, and the shift needs no tracing: a port tile after a solve = placement port + (values[cls] - flat[cls]) + offset. Works for any topology (no roles).

## Recipe: JunctionNodeInput field -> graph source
- paths[i].pieces: route pieces (RenderJunctionTrackPlacement out-param), in the Q1 key order (port position, trackdir sequence). Each piece tagged by Q7.
- paths[i].from_slot/to_slot/movement: the route's JunctionLanePath (from, to, movement), unchanged.
- paths[i].from/to (roles): T: `TRoleOfSlot` table (slot -> EIn, WOut, NIn, SOut, WIn, EOut); other topologies: EIn.
- through[i]/exit[i]: topology.movements[movement] groups' `main` (both main / first main, second not).
- used: drop (builder never reads it); for slots/events use the route union plus prio-element tiles.
- events[i]: Q4 rule (graph nodes of the lane path on placement.nodes, plus lane split/merge from placement.copies / placement.edges SBend spans of doubled edges).
- slots[i][k]: Q5 geometric rule (no signals needed); with signal tokens: add token facing and "no signal on the track".
- bridges: the routes' bridge runs, normalised (x+y ascending), deduped, in route-appearance order (placement.bridges has the same set, other order); z/tunnel default.
- (template) anchor: first exit lane path's port slots: ports[to] x, ports[from] y.
Not derivable from the graph: nothing found. Open (INFERRED): prio-element tiles for the slot rule once signals exist (ST2 geometry), structure-derived prio side in place of joiner_row, AddCrossings' under-bridge set from `crossed` (outcome verified equal, rule not diffed), JunctionNodeTopologyT's hub definition.
