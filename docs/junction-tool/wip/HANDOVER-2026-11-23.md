## Rules found and fixed today, all judged by the suite
- **Lead (D429, D430, F1):** a leg's S-bend at its node that lands on a sibling's heading needs one game piece of travel first.
- **`end_node`:** a structure's end run stays off a node's switch tile.
- **`cross_piece`:** a crossing sits on a piece with length.
- **Footprint:** end runs count a diagonal crosser's footprint (always on).
- **F2:** D412's code matched to its wording (in-port lines only), so the grid reaches node legs.
- **F3:** contracted lines turn one eighth at a time.
- **D431:** the E5 pipeline is a measurement tool. Slots is built from suite-cleared rules, sides by construction, and whole tiles in Slots itself.
- **D432:** Slots writes rows over contracted lines.
- **D433:** a zero-length node-to-node track (the trident).

## Slots items found
- Slots keeps the flank between two used S-bend inserts.
- Production `steps` cannot hold an S-bend at a track's end (planar_draw.cpp:556).
- The drawing program cannot draw a map with a copy on a PORT line: the line's parts leave `expanded.ports[].lines` naming a line that now ends at a node ("line A1 does not end at its port", planar_draw.cpp ~700).
- The program's `grid` seeds only axis runs with a least length: in the uncontracted writing (flex flanks may be 0) its gridded drawings are off the domain's grid (L1: every track). Moot under D432 (contracted lines have no zero pieces), but every hub run through the old program is off-grid.
