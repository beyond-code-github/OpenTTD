2. NOT expressible purely as channel-end headings. Channel headings (BuildPlanarPaths) do not read ties at all: every channel's first/last heading is its port heading (C:1221, 1366; C:1419 asserts both join legs arrive on h). The tie only picks which leg is the undiverted one inside a fixed component (the other gets a +-45 deg diagonal, side from its own turn sign, so side is not a free +-1 at a tie). Beyond headings it changes: component construction (Fray/Join lane order, prio spread side, JoinEntry offsets far_left), the gap-step list (G), merge exit steps (joiner side), ladders/face order at the site, and Flex offsets. Shape program (planar_shape.cpp:95-135) fixes channel start = port heading / in channel end, so it has no variable to carry a tie; a tie would need a new variable "which leg takes the diagonal" = start heading of leg X in {h, h+side_X} (an integer 0/1 per site), and the components must then be rebuilt from it. Only a shape that *forces* straightness (net turn / least turning at the diagonals) can choose it: today's cost counts net turns only, and both choices give the same net turn (equal |turn|), so the program has nothing to rank by. Any decision would need a different criterion (room/area), i.e. it stays a variant or becomes a derived rule.
