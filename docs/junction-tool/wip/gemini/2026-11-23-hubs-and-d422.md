# For Gemini: the pipeline on T2, T3, LL2, and whether D422's split is the real limit

## Background (short)
Our drawing pipeline (D422) for one hub: discovery LP rounds (flex inserts priced by IRL1, keep-apart rows elastic, **no curve-spacing rows on inserts**), then commit the inserts used (>= 1 half tile; their curve rows switch on), commit rounds (keep-apart and curve rows elastic), one prune (hold at 0 the committed inserts whose own curve rows still stretch), more rounds, then an integer final. Slack costs 1 per half tile; keep-apart directions are fixed from the previous round's drawing. Legal = last LP round at slack 0.

## Our reading
Each correct keep-apart fix sends the rounds down a different path, and the pipeline keeps ending a unit short on rows it has no move for: plain curve rows between Shape's fixed bends, or a prune whose held inserts make hard rows infeasible. That points at D422's split itself: discovery chooses inserts and geometry without curve rows on the inserts, so the commit has to repair what discovery packed.

## Two options we are weighing
1. **Robustness patch:** undo a prune that leaves the round infeasible and carry on from the commit drawing. Generic, cannot make anything worse, gets T3 and LL2 to their finals so we see their true remaining slack. Does not address plain curve rows short by 1.
2. **Redesign discovery:** give inserts curve rows during discovery, so discovery never packs past what is curve-legal. The difficulty that made us split in the first place: an insert's curve rows only apply when the insert is used (length > 0), which is a yes/no per insert; in an LP that is either a binary (we tried integer optional-flex models: too slow on 197) or a relaxation.

## Questions
1. Is option 1 worth doing first, or is it hiding the real problem?
2. For option 2: what LP-friendly ways are there to impose a spacing rule that applies only when an optional segment has positive length? We know big-M with binaries (slow), and fixing the yes/no from the previous round (our current commit). Is there a convex or iterative scheme (e.g. reweighting, perspective-style relaxations, a sequence of LPs that converges) known to work for "optional bends with minimum spacing between consecutive bends"?
3. Plain curve rows between two fixed bends that end 1 short: the only freedom is the length of the pieces between them, which keep-apart rows (directions fixed from the previous drawing) may be blocking. Would re-picking keep-apart directions near the short curve row be the right move, or is there a better standard repair?
