# For Gemini: keep-apart rows against the expert's hub, and where bends may go

## Setup (recap)
- We draw an OpenTTD rail hub as an LP/MIP on a half-tile grid. The shape is fixed: per track a heading list (8 directions), and the piece each crossing sits on. Lengths are the unknowns: an axis piece is 2k half tiles (k >= 1), a diagonal piece moves (+-1, +-1) per unit (>= 1).
- **Flex points:** on a free stretch (between two events, not inside a bridge/tunnel span or crossing lattice) of exactly one piece at heading h, we insert two bend pairs, h -> h-1 -> h and h -> h+1 -> h, each with length >= 0. So a step sideways (S-bend) can appear there, or not.
- **Answer key:** the expert's hub (PSG 197) from the save. 324 points (track ends, crossing points) are pinned within +-w half tiles plus one common shift.
- **Keep-apart (pairwise):** in each non-convex face, every non-adjacent wall pair is kept apart along the walls' normals (or, for parallel walls, the normal or the shared direction), on one of four (axis, side) choices. Here the choice is fixed from a reference drawing (the candidate with the largest least margin), so it is an LP. We re-pick from the LP's own drawing until it stops improving.

## Results, window 8
- **Base rules:** pieces, nodes, crossings, spans, ports. With pins, LP slack 0 and the integer program is feasible. The one gap was a crossing at the crosser's bend, which the expert builds over a tunnel; we now allow it.
- **Keep-apart:** base rows hard, slack only on keep-apart rows. Slack runs 624 -> 118 -> 110 -> 108 -> 102 -> 102 over re-picks, ending at 27 rows, each <= 8.
- **Window 4:** the base rows alone are infeasible, on the same tracks as below.

## Where the residual sits
1. **Around one node (about half the residual).** 8 of the expert's 50 steps sit on free stretches of two pieces, where we place no flex. Example: our shape for L95 is W, NW; the expert builds W 6, SW 4, W 10, NW 2.
   - Flexing every piece of every free stretch found all 8 steps.
   - But it multiplied the flex points (660), so the convex-cell refinement got much worse, and it broke a landing rule.
2. **A zero-length line.** The expert has a line of length 0 (a split on the box-edge tile). Our keep-apart rows still hold its pieces apart from a neighbour, as if they were walls.
3. **Two parallel lines that bulge out and back together** (both 2, 1, 2, 3, 2). Slack 12.

## Questions
1. **Where should bend pairs go on a multi-piece free stretch?**
   - Our candidates:
     - (A) only on the end piece next to a node or port;
     - (B) on every piece;
     - (C) on the first and last piece.
   - Is there a principled rule? For example, from octilinear metro-map layout or the compaction step of topology-shape-metrics: where do they allow optional bends on an edge that already has bends, and at what cost to the convex refinement?
   - Which would you pick? The expert's 8 cases, each as stretch (bounds), then where the step sits:
     - On the last piece (6 cases):
       - SW W (node-node): on W, both sides;
       - SW W (node-node): on W;
       - SE S (node-node): on S;
       - W SW (node-crossing): on SW;
       - NW W (node-node): on W, twice;
       - W SW (crossing-node): on SW.
     - On the first piece (2 cases):
       - W NW (port-node): on W;
       - W NW (crossing-node): on W.
   - So the step always sits on an end piece, but not always the one next to the node.
2. **Zero-length walls in keep-apart rows.** A wall whose piece may have length 0 should impose no spacing when it is 0. Is there a linear (no binary) way to write this? For example, scale the spacing by a length indicator, or exempt the pair when either piece is may-be-zero. Or is one binary per may-be-zero piece the honest cost?
3. **Is 102 slack over 27 rows "matches"?** Each row is <= 8 half tiles, at window 8, with sides from a local search. Or is fixed-point re-picking too weak to trust? Would you take sides from the expert's raw tracks instead, accepting that some of the expert's pieces have no counterpart in our shape?
