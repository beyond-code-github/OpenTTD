2. The router lays no rise over L4 on L7's column, for three rules, with the numbers from the `RISE` / `STATE` prints:
   - Start state (27,36) h4: `fresh true`, so `!s.fresh && s.straight` fails: no rise from the first piece. Also `at_node(at)` is true there (the merge node (27,36) is the head piece's start point), so `rise_moves` refuses the head even if the state were allowed. The head tile (13,18) itself is free.
   - State (27,38) h4: `fresh false straight true`, but the head piece 1 is tile (13,19), which holds L4's piece (`head.occupied true`): head tile not free.
   - States (27,40), (27,42), (27,44): heads free, no node, but no middle holds a piece (L4 is behind them), so no crosser: no rise.
   - The existing track's rise (L4 over L7): L4's piece on the tile is h6 between h7 pieces, not a straight run of three axis pieces: `existing_rise` refuses.
   - Hands: none (`hands 0`; L7's structure has hand_before = hand_after = 0), `spare_middles` false would pass (the first and last middle is the one middle holding L4), `bridge_limit` 10 is no limit, `max_expansions` is not hit. 3. Variants (all four hubs, pull by 0 or 2 half tiles, `turn`/`swap` 1 or 0 gives the same):

The router's search is complete over its rules; the rules refuse a bridge whose first head piece is the first piece of a leg leaving a node.

## Cause and smallest fix
`rise_moves` (planar_groove.cpp) refuses a head whose start point is a node point, and the search lays a rise only at a non-fresh straight state, so a leg that starts at a node can never open with a bridge head; the hub and the judge allow one (the head tile is the first tile past the node's switch tile). The smallest fix: allow the rise at the leg's own first state when `start_at_node`, the point is `request.start` and the heading is `request.start_heading`:
- in `rise_moves`: `at_node(at)` becomes `(at_node(at) && !(request.start_at_node && at == request.start && heading == request.start_heading))`;
- at the call: `!s.fresh && s.straight` becomes `(s.fresh ? (request.start_at_node && s.x == request.start[0] && s.y == request.start[1] && s.heading == request.start_heading) : s.straight)`, still with `s.heading % 2 == 0`.
Tried temporarily (env-guarded): on all four hubs, with `rip` true or false, `turn` either way, pulls of 0 and 2 half tiles, the hard pass succeeds, the structures are L2:1..4, L3:12..15, L7:0..2 (L7's bridge kept), L4 untouched, and the result passes the judge with the input's allowed set. Not run: the full tests, the other rise rules at a goal node (the mirror, a leg ending at a node with a head as the last piece, is untested), and the cost of the full pf3 pull-in with the fix.
