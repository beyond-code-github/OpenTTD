## 2. From the save to the first machine-readable form

- Load check of the whole corpus (RECON-psg-saves.md "Method"): build `build-play` binary, run `openttd -v null:ticks=5 -s null -m null -g <save>` with `scripts/game_start.scr` containing `script <log>`, `map_hotspots <k> [window=48]` and `quit`; scratch config dir (later GR1 pass uses the engineer's data dir for NewGRFs). Output `OD/psg/loadcheck.tsv` (name, exit, missing GRFs, error, hotspot) and `OD/psg/loadlogs/<name>.log` (183 files).
- Export commands (src/console_cmds.cpp:549, 574, 607; writer `src/junction/game/junction_map_export.{h,cpp}`, tests `src/tests/junction/game/junction_map_export.cpp`): `map_export x0 y0 x1 y1 file.json` (rail, bridge heads, stations, crossings), `map_export_station id margin file`, `map_hotspots k [window]`, `junction_terrain_dump x y w h file` (needs company 0).
- bbh.json format (head of `OD/psg/anatomy/psg197/bbh.json`): top keys `box` {x0,x1,y0,y1} = 76,128,136,203; `map_size` {256,512}; `orientation` string ("map x increases towards screen SW, y towards screen SE; tile (0,0) is the north corner; edges: NE=x-1, SE=y+1, SW=x+1, NW=y-1"); `tiles[]`, each with `x`, `y`, `tile_type` (rail), `kind` (signals/...), `tracks` (X, Y, Left, Right, Upper, Lower), `height`, `owner`, `rail_type`, `signals[]` {track, trackdir, exit_edge, state, type (block/entry/exit/combo/path/path_oneway), variant}. Box counts (ANATOMY:7): 555 plain track, 501 signal tiles, 105 tunnel heads, 3 bridge tiles, 12 station tiles, 1 depot.
- Note: the trace loads the SAVE through `c2.load(save)` (anatomy.py:13, `Net.__init__`), not bbh.json; `OD/psg/maps/<save>/<x>_<y>.json` are whole-map exports (RECON-psg-hubs.md "Method": every 256x256 box up to 4096x4096, 178 saves, 1.1 GB, empty boxes deleted). `c2.load` is at review-g4/py/c2.py:51 (body not read; assumed to read a maps/ JSON or run an export: unverified).
- The `OD/mapx` directory (38 entries) holds other exports (psg186_*.json, psg219_*.json, fled*.json, bub_overflow...); no psg197 file in it. `OD/psg/psg197_{1..4}.json` are the top-4 hotspot exports (RECON-psg-saves.md row 197), not the hub.
- Boundary and ports: the analysis box 76,137,128,198 is `BOX` in `TR/net.py:7` (a widening of the engineer's 81,141-123,198 hub box, "cuts the right arm mid-structure"). Ports = lanes crossing the box edge, from `c2.analyse_box` (`ctx['lanes']`, with side and position along the edge); 16 lanes kept by `KEEP` (core.py:8): out N84 N85 S88 S89 S90 E164 E166 E167; in N90 N91 S81 S82 S83 E169 E173 E174. "Lane id = edge coordinate; out | in order across the arm". ANATOMY records E164 is the y 163 line after an S-bend and E173 shifts to y 172 inside; E173's split is on the edge cell 128,173 (port line CD2 length 0, gaps §11).
- The arm naming `ARM={'N':'N','E':'E','W':'SW'}` (net.py:8) maps the tool's sides to the engineer's arms; psg197.txt keeps the save's sides (header "Frame: the save's sides kept").
