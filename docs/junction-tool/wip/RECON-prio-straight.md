## Answers
1. Yes. A prio is NOT a component with its own shape: the ML lane S gets one straight segment (heading h, >= 2P+2 half-units, ends at the merge) and the row is a free h-heading stub of length 2P beside it, attached only through the merge point (fixed: starts 2P before it, 2 half-units to the side). The row is a reservation, not a strand in the channel. So the ML under a prio is pinned straight, axis, length >= 2P+2 plus joiner/crossing deck lengths, and that is why T3 (doubled prio channel, crossings stacked, JoinEntry) runs long: straight >= prio length on every lane, per crossed joiner another P-spaced doubled stretch (PC:984-996), plus 2P+2 at the last.
2. Smallest step: in the signal pass only (junction_signals.cpp:136-175) and the checker shape clauses (:1360-1403), generalise to per-piece side tile for gentle cases first: let the ML coverage be a path of pieces (axis plus diagonals), row tile = side tile of each ML piece (row = ML path offset by 1 tile perpendicular to the ML, on the side opposite the joiner); joins only on axis pieces. Composer change after that: drop `AddSeg(S,h,2P+2)` for optional bends in the coverage (a min-length axis tail near the merge and each join stays). Row shape: parallel offset of the ML path, one tile; at a bend the offset tile shifts as the ML's side corner (tracks h1/h2 pattern per piece). A first step with no composer change: mapped output for ML S-bends outside the straight pieces is already allowed; test the signal pass + checker on a hand layout with a bend in coverage; G9b should stay green by itself.
