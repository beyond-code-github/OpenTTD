# DESIGN-N3: node template, render, structure search (D182-D184)

Status: orchestrator design, 2026-11-11. Builds on DESIGN-nodes rev 3 (§3, §4a, §4b, §9), FLAT-T-CHAINS.md, N0a/N0b/N1/N2 (merged).

## 1. Geometry of the template (from the flat T, D184)
- Coordinates: the flat layout's (after the crop). Rows = y, the junction's long axis = x.
- **Paths**: the checker's traced paths (MakeJunctionCheckContext(...).paths, as ExtractJunctionChains reads them). A **run** = consecutive pieces of one path with the same direction.
- **Points**: the pieces the model positions: the first and last piece of every run on every path, every switch piece (SwitchEventsOf), the first and last on_bridge piece of every bridge on a path. A point is identified by (tile, trackdir); paths that share a piece share the point.
- **Links**: consecutive points on one path. A link is **free** iff both points are on the same row, the path travels along X between them (trackdirs of the X axis), and no piece from the first to the last is on_bridge. Every other link is **rigid** (column runs, diagonals, curves between adjacent pieces, bridge spans).
- **Classes**: union-find over points across rigid links. Each class is one variable of JunctionPositions; a point's x = value(class) + offset (offset from the flat). Every piece of a rigid run belongs to its class with an offset too (needed for crossings).
- **Direction**: on one path all free links travel the same way in x (assert; true for the T). So between two points p, q of a path, units(q) - units(p) = flat units + 2 * dir * ((x_q - x_p) - flat(x_q - x_p)). Every unit rule becomes a difference constraint between two classes (or a constant check when both are one class).

## 2. Constraints (the template)
1. Free link p->q: dir * (x_q - x_p) >= 1.
2. Curve gaps (N0a): per path, JunctionCurveGaps(hands, tl, curve_speed, reference) over the path's curves; each gap g between curve points ci, cj -> the unit formula of §1.
3. Prio coverage (N0b's rule, JunctionChainViolations): for every prio merge m on a main-line path, every curve c before m: units(m) - units(c) >= 2p; every split s before m: units(m) - units(s) >= 2p + 1.
4. Crossings: for every bridge (heads h1, h2 on one path, h1 first in travel) and every piece of another path whose tile is strictly between the heads in the flat: that piece's x strictly between the heads' x (two constraints, >= 1 each). The piece is on a rigid run (assert).
5. Anchor: the class of the last piece of the EIn->SOut path (the S port, fixed by the frame, D178) is fixed to its flat value.
Not in the template yet, found by the oracle (CheckJunctionRules) in tests: signal slots, collisions between unrelated tracks, D172's span windows beyond rule 4. Added only when a test shows one (simplicity rule).

## 3. Render
For values of every class: every point at (value + offset, flat y); every rigid run's pieces translated with their class; every free link filled with axis pieces along its row; bridges translated with their heads' class; E/W port end runs extended so the crop of FinishJunctionCandidate (content +- 2) gives the box. Then NormaliseJunctionLayout, PlaceJunctionSignals, NormaliseJunctionLayout (as FinishJunctionCandidate does). Round trip: render(flat values) == the flat layout.

## 4. Structure (N3b/N3c, designed after N3a measures the template)
- A structure = a set of **shifts**: (free link, side +-1). A shift is an S-bend pattern (two opposite 45-degree curves with a one-row diagonal) inside that link; every point after it on the path takes dy += side until the next shift on that path. Rigid diagonal links whose ends get different dy change their x offset by one per row (45 degrees) and their units by 2 per row; a free link or bridge whose ends get different dy is invalid.
- Facts (N2) per structure: a free link on row r covering column c that is not Straight, or a break between c and c+1 (StraightRun false): JunctionPositions::AddAvoid with an auxiliary var for x_b - 1 for breaks. A rigid piece whose tile fails its fact (Straight/Switch/Half): RestrictDomain on its class.
- Search: best-first by cost (added curves, then tiles), start = flat structure; on infeasibility the failing fact's link gets the repair children: a shift to row r-1 or r+1 before the fact (D182: may stay shifted; another fact or rule later adds the shift back). Bound: at most rows-available shifts per line. Collision of rendered tracks = this structure fails (measured; becomes a constraint if it recurs).
- Outer tests (N3c): the house at (xI-1, 0), the unbuildable hub tile, the W-end incline: each builds, CheckJunctionRules clean, no router call.
- N3c scope note: this step realises a shift as a detour within one free link (shift out and back before the next point). Staying shifted past a node (D182) is a later repair kind, added only when a measured case needs it.

## 5. The Y axis: depth in the graph (N0c, D185a, D189)
N0c builds the node graph from the rules: topology = ports + movements (D189), one crossing assignment as input, everything else derived. Two steps.

**N0c1: Y runs are free (this section).** Every rule of §1-§2 applies to Y as to X:
- A link is **free along X** (same row, X trackdirs, no on_bridge piece) or **free along Y** (same column, Y trackdirs, no on_bridge piece); every other link is rigid.
- Two systems of classes over one JunctionPositions: X classes = union over rigid links and Y-free links (a Y run keeps its column); Y classes = union over rigid links and X-free links (an X run keeps its row). Variables: X classes first [0, nx), then Y classes [nx, nx + ny); `flat` holds both. A point's tile = (value(cls) + tile.x - flat[cls], value(ycls) + tile.y - flat[ycls]).
- Unit rules: between points p, q on a path, units(q) - units(p) = U + 2 dir_x (Δx - Fx) + 2 dir_y (Δy - Fy). Differences of X classes when only the X classes differ, of Y classes when only the Y classes differ, a constant check when neither; when both differ the template fails ("gap spans free links on both axes"). In the T no unit rule spans both (curves sit together on one side of each vertical leg), so both systems stay difference constraints.
- Crossings (rule 4) for a bridge along axis A on line c of the other axis B: a rigid piece of another path on line c strictly between the heads: strictly between them along A, and on line c along B (two diffs, k 0); a piece inside a free link along B: that link's ends straddle c along B (>= 1 each side); a piece inside a free link along A: template error.
- Box edges (rule 6) on both axes. Anchors: X = the S port end's class (as before); Y = the class of the first point of EIn->SOut (on A: A's row is fixed by the frame). Depth = the S/N port ends' y, solved.
- Facts: the solve fixes Y first (snap to flat, no facts), then X with the rows known: a Y run's interior is a column restriction on its X class (Straight along Y at every interior row, heights connected between interior rows). A house on a vertical leg moves the leg's column; lengthening a leg to avoid terrain is not modelled yet (add when measured).
- The detour search stays on X links.

**N0c2: the skeleton from the rules (designed after N0c1 measures).** Diagonals are rigid (DESIGN-nodes §7) with a length set by the curve rule for the spec (a same-hand pair of 45-degree curves needs min(2 TL - 1, CL) units: 5 at 160 km/h, 7 at 196), so the graph for a spec is generated, not read from a routed layout: per movement, the turn program from its ports, the node order (splits before merges, D189), sides and the crossing assignment, with diagonals at their rule length and free runs solved. Outer tests: the test spec gives a rule-clean T no larger than today's; 140/160/196 km/h on flat land give clean Ts with no router call.

## 6. Free diagonals and the two-phase solve (N0c2; RECON-turn-programs)
RECON-turn-programs: at the test spec almost every length is at its rule minimum; only the same-hand corners (A->S, W->S, N->E: 5 half pieces) grow with speed (7 at 180/196 km/h), two of them pass under the W line's bridges, and N->W's 13-half diagonal must stretch whenever the N split moves down. So diagonals are variables too.
- **Free diagonal**: a diagonal run of >= 3 half pieces with no on_bridge piece and no piece under a Y-axis bridge (today's D2 stays rigid: it is column-fixed). Its link is first half piece p -> last half piece q. Two half pieces = one map step (dx, dy) of its direction, so with m extra steps: halves = flat + 2m, x_q - x_p = flat + dx m, y_q - y_p = flat + dy m; m >= -(flat halves - 2) / 2 (rounded toward zero). Free diagonals join no class in either system.
- **Monotone paths**: on a path all X-moving free links (X runs, free diagonals) share one x sign d_x, all Y-moving ones (Y runs, free diagonals) one y sign d_y; otherwise a template error. True for the T (2-half S-bends stay rigid).
- **Units**: between points p, q of a path, units change = 2 d_x Δx + 2 d_y Δy - 2 Σm (Δ = change from flat of q - p; Σm over the free diagonals between). With no X-run between p and q this is 2 d_y Δy: a **Y difference**, added up front. With an X-run between, it is added **after the Y snap** with Δy and m known: 2 d_x Δx >= g - U - 2 d_y Δy + 2 Σm, an X difference.
- **Phases**: (1) all static diffs; (2) snap the Y variables (nearest flat); (3) late X constraints: each free diagonal's x equality, the late unit rules, and X-axis bridges over free diagonals (the diagonal's tiles on the bridge row, from its raster at the known length, strictly between the heads); (4) X facts and X snap. Static Y side of a bridge over a free diagonal: the bridge row lies within the diagonal's rows (inclusive).
- Facts on a free diagonal's interior: every tile of its raster fits a half piece, a domain restriction on p's X class after the Y snap.
- The Y snap does not see X needs (a Y choice can make X infeasible): measured, not modelled, in this step.

## 7. Occupancy: unrelated tracks never share or touch (D193; AUDIT-rule-coverage item 1)
After the Y snap every element's row is known and its x is a class value plus an offset, so occupancy is a per-row order rule over X (phase 3, after the late constraints):
- **Elements on a row** (current rows): every non-bridge piece (one tile); every bridge head (one tile, the bridge's class); the interior of a free X run (tiles x_p + d .. x_q - d); each interior tile of a free Y run (its column); each interior raster tile of a free diagonal (x_p + offset). Elements whose flat tiles are identical (a switch tile's two pieces) form one group: equal x (two diffs), one entry in the chain.
- **Chain**: per current row, sort the elements by their flat lo x. For consecutive a, b: if flat hi_a >= flat lo_b they overlap in the flat order: failure Occupancy (the row) — two things the topology stacks are now on one row (the Y snap is blind to X). Otherwise lo_b - hi_a >= gap: gap = min(2, flat lo_b - flat hi_a) when a and b lie on one flat row (the flat T is legal, so its gaps are); else 2 when their tracks touch across the facing edges (a's tile reaches its +x edge and b's its -x edge), else 1 (OC1: a half piece beside a Y track at a split, or a stretched corner beside a bridge head, are legal at gap 1).
- One owner: each element owns a set of free links (its own link for a run interior or diagonal raster tile; the links it ends for a point piece; empty for bridge heads and other pieces). Consecutive entries whose sets intersect get no constraint and no overlap failure: a link's tiles and its endpoints are related by the link's own constraints (OC1 measured a stretched stair's two tiles on one row, and a diagonal's raster tied with its own endpoint). Ties in the sort: flat hi, then element index.
- Consecutive constraints suffice (the chain is transitive). Not covered yet: vertical edge contact (a Y-track end on the row above/below another Y track at the same x); measured before adding.

## 8. The prio row as a reserved occupancy element (D193; RECON-prio-footprint)
Per prio merge (AddPathDiffs' prio merges): M = the merge point on the ML path, d = the ML's x direction, side n = minus the row offset of the joiner's piece before M (the prio lies opposite the joiner, D75/D87). Reserved element on current row (row of M) + n: x from x_M - (p + 1) d to x_M (coverage p tiles plus D107's piece), track bits X, empty owner set, flat row = flat row of M + n, flat lo/hi at flat values. It enters the §7 chain like any element, so the legal flat T keeps its gaps (same flat row) and new neighbours need gap 2 at a touching end. Not covered (T3-type, measured first): one free ML tile per required block, PrioReach residuals, D111 bending prios.

## 9. Vertical order in the Y phase (OC2; RU1 finding)
RU1 at tl 8: the waiting-room rule grows a diagonal by one step, and the nearest-flat Y snap puts the moved class onto a row another element occupies: Occupancy at row 12 in the X phase. The Y phase must keep the topology's vertical stacking, as §7 keeps the horizontal order:
- **Y elements** (static, before the Y snap), each with a column key = its flat x and a row = (Y variable, offset): every non-bridge piece and bridge head (its ycls); every flat interior tile of a free X run (the run's ycls; one element per tile); a free Y run's interior as one interval element [y_p + d, y_q - d] in its column; every flat raster tile of a free diagonal except q: (p's ycls, its flat row offset from p) — the stretch adds tiles near q, so tiles from p keep their offset; q is a piece.
- **Chain per flat column**: sort by flat row (ties: flat hi, then index); consecutive a (above), b: owner sets intersect -> skip; flat hi_a >= flat lo_b -> template error (cannot happen in a legal T); else lo_b - hi_a >= min(2, flat lo_b - flat hi_a) over the Y variables. Gap 2 is kept wherever the flat had it, so no new vertical edge contact.
- It is conservative: columns are flat columns, so two elements the X phase moves apart horizontally still keep their vertical order. The X-phase chain (§7) stays the exact check.
