# #openttdcoop station rules for a station generator

Date: 2026-11-08. Scope: sourced rule base for procedurally generated stations (parallel track to the junction tool). Format follows `RULES-coop.md`. Rules marked "(implied)" are inferred, not stated. All ABR07 examples are "made for TL3".

Sources (short names used in the Source column):

- **ABR07**: V453000, "Advanced Building Revue 07: Stations" (the main source; `abr/07-...stations.txt`).
- **ABR09**, **ABR13**: self-regulating stations I (V453000) and II (LoPo).
- **ABR11**: refit stations (V453000).
- **ABR05**: S-Bahns and city networks. **ABR06**: hubs. **ABR10**: invisible hubs (nothing station-specific found in ABR10 beyond links to ABR07/09).
- **MT**: coop wiki "Merging Tracks". **RS**: "Ruleset". **GL**: "Glossary". **JN**: "Junctionary" main page. **SML**: "Shift Mainlines". Mainline page: no station passages.
- **IMG**: images by filename (coop wiki files, or `abr/images/`). Only images I viewed are cited.

Important limit: the sources are qualitative. There are no formulas for platform count, platform length, waiting-bay length or signal spacing. The Junctionary station sheets (`JunctionaryBasic/Pickup/Drop/Combined/SpecialCaseStations.png`, `JunctionaryALLStations.png`) exist locally only as 75x75 icons, and the Junctionary text copy has no station entries, so the taxonomy basic/pickup/drop/combined/special-case is known from file names and headings only, not from content.

## 1. Station types

| ID | Rule | Why | Source | Generator impact |
|---|---|---|---|---|
| S1 | Ro-ro (roll in, roll out): trains enter and exit at opposing ends. Incoming trains do not block leaving trains. It is the standard type. | No real disadvantages. | GL: "A train station where trains enter and exit from oppopsing sides." ABR07: "Roll in – roll out stations are considered standard since they don't really have any disadvantages." | **param** (default type = ro-ro) |
| S2 | Terminus: entrance and exit on the same side. It is not worse in throughput if built properly, only in platform usage and compactness. | Entry, exit and balancing share one spot. | ABR07: "The only real difference is that you use the same side for both entrance and exit." "terminus stations tend to have worse platform usage, but if built properly, they are as effective as a roro in total station throughput" | **param** (type = terminus; needs the X or X-less variant, see 5) |
| S3 | Terminus has a rebuild cost: entry and exit sit together, so a fix touches both. | Coupled layout. | ABR07: "you usually have to rebuild both of them in case something breaks" | **design** (generate entry and exit as separable modules) |
| S4 | The first design question is purpose: pickup, drop, or both. Copying a station without regard to its purpose fails. | Requirements differ by purpose. | ABR07: "The first and probably most important aspect is whether the station is a pickup, a drop, or even both." "copying a station is almost never the right way to go!" | **param** (role = pickup / drop / combined) |
| S5 | Pickup: the station can fill up, so entry needs a check that refuses trains when full. Multi-line pickups need a balanced entrance. | One wave of trains fills it; otherwise one half fills and the other stays empty. | ABR07: "Is it possible that the station could get full ... Of course! It is a pickup" "Balanced entrance for multi-incoming-line pickups is a must" | **design** (pickup => entry check + balanced entry when lines > 1) |
| S6 | Drop: can be built "dirtier". With enough platforms it never fills, so no entry check and no balancing are required (balancing still helps). | Unloading is fast; station built for full throughput. | ABR07: "we don't need any control for letting trains in if station is full" "Balancing the entrance isn't that necessary either!" | **design** (drop => no entry check by default) |
| S7 | Combined and special types (pax, SRNW, refit) stay longer and are one-offs. Pax stations load and unload, so occupy platforms longer. | Long dwell times. | ABR07: "pax stations because they usually stay for some extra-long time since they mostly both load and unload" | **param** (dwell time class; see section 9) |
| S8 | Junctionary taxonomy: Basic, Pickup, Drop, Combined, Special Case, plus an overview sheet. Content not available as text. | n/a | IMG: `JunctionaryBasicStations.png`, `JunctionaryPickupStations.png`, `JunctionaryDropStations.png`, `JunctionaryCombinedStations.png`, `JunctionarySpecialCaseStations.png` (75x75 icons only) | **gap** (see "What the sources don't say") |
| S9 | A "combination of ro-ro and terminus" exists (overflow-style stations with a depot). Out of scope here. | n/a | IMAGE-INDEX caption from ABR04/08: "an interesting version of a combination of both ro-ro and terminus station" | **gap** |
| S10 | Never connect a station directly to the mainline; always via a sideline (and a sideline hub). Main stations hang off a main station hub (MSH). | A station slows a fast mainline. | RS: "Never ever connect a station directly to the mainline. This makes a fast mainline slow. Always connect a station via a sideline." GL: "Main station hub: A hub that connects main stations to mainlines" | **check** (station entry is a sideline, not an ML) |

## 2. Platforms

| ID | Rule | Why | Source | Generator impact |
|---|---|---|---|---|
| S11 | Platform count has no standalone answer. It depends on entry response time, balancing, train speed, acceleration, unloading time and TL. Test the real trains. | Faster feed to platforms means fewer platforms. | ABR07: "this sentence makes no sense until you provide all important information on which the platform count actually depends!" "If you don't know the train set, I strongly recommend to test trains" | **param** (platform count is a user input, not derived) |
| S12 | Balanced entrances need fewer platforms per line than unbalanced ones, because lines are not all full. | Trains re-balance onto free platforms. | ABR07: "we expect that those lines aren't going to be fully loaded and that way they need lower average amount of platforms per line" | **design** (informational; no formula) |
| S13 | Stations in a game are all equally long. Smallest usually has 2 platforms. Larger maps (for example 1024x1024) use larger stations because long running times cause queues. | Uniformity; queue avoidance. | RS: "Stations are all equally long ... Usually the smallest stations have 2 platforms but on larger games, like 1024x1024, you should stick to even larger stations" | **param** (platform length = game constant; min platforms 2) |
| S14 | Platform length versus train length: not stated numerically. Platform capacity is expressed in TL (train length in tiles), e.g. "3 tiles where trains stop eventually" in an ABR07 figure, and 1 TL braking space and 1 TL waiting bays. Implied: platform >= TL. Refit "TL+1 station" is one tile longer than the train. | Trains must fit. | ABR07 figure note: "lines show the 3 tiles where trains stop eventually" (TL3 examples). ABR11: "The pickup part is just made a tile longer" | **param** (implied: platform length = TL, or TL+1 for the refit double-visit) |
| S15 | Synced station: every path through every platform has the same total length, so trains leave in the same formation as they arrived (like synced bridges). It needs a direct entrance, equal dwell time per train (easiest: one cargo type), and no balancing. | Trains never meet, so none must stop. Useful for fast, slow-accelerating trains. | ABR07: "all platforms take equally long path to go into and out of in total" "Any balancing could break it" | **param** (synced yes/no; synced => direct entry, no balancer) |
| S16 | A synced terminus is possible only without the X: "you can make a synced terminus this way if you adjust the lengths correctly and make a direct entrance". | Equal path lengths. | ABR07 (3.2.2). IMG: `abr/images/ABR07_Xless.png` | **param** |
| S17 | Waiting bays right in front of the platforms free a platform sooner and raise platform efficiency, unless the trains accelerate too slowly to benefit. | Trains enter the platform immediately after it frees. | ABR07: "One of possible improvements ... is making waiting bays right in front of the platforms." | **design** |
| S18 | Platform usage depends on how far the "releaser signal" sits into the platform path. Longer path to the platform means lower platform usage. | Trains take longer to reach the platform. | ABR07: "it is based on how far is the 'releaser signal' into the platforms" | **design** |

## 3. Entry

| ID | Rule | Why | Source | Generator impact |
|---|---|---|---|---|
| S19 | The incoming line is the busiest line. It should never slow down if maximum throughput is the aim. | Full-speed station. | ABR07: "This rail should not ever slow down if we aim for max throughput." | **check** (no station signal or bay may block the incoming line) |
| S20 | Two entry styles: **buffered** (trains wait in waiting bays for a free platform) and **direct** (trains do not stop after the split until they reach the platform). | Platform distribution is the main entry job. | ABR07: "wait at waiting bays in front of stations until they reach the station. Secondly – making them not stop until they reach the station." | **param** (entry = buffered / direct) |
| S21 | Use buffered when the entrance is balanced and trains accelerate well. Direct only works when no other train can enter the path, so it is for unbalanced stations. | Balanced direct paths cross, so one train must stop. | ABR07: "Making waiting bays usually applies to stations with balanced entrance and trains with good acceleration. The direct connection is much easier to maintain when the stations aren't balanced" | **design** (balanced => buffered; synced => direct) |
| S22 | Trains with weak acceleration are better served by direct entry, because waiting bays slow them too much. Fast-accelerating trains lose little in bays. | Restart cost. | ABR07: "When we have trains that just accelerate very slowly, waiting bays might slow them down too much!" | **param** (acceleration class chooses buffered vs direct) |
| S23 | "Balanced entrance" in coop means trains from every incoming line can join any platform. It does not mean equal traffic per platform. | Re-balancing onto free platforms, easier unjamming. | ABR07: "Usually a station entry where trains from every incoming line are able to join any platform." "If there is any jam or problem, trains just re-balance to the free platforms" | **param** (balanced yes/no) |
| S24 | Do not balance by default: balancing is "very far from truth" a must. Unbalanced stations expand by cloning. | Cost and space. | ABR07: "Too often people think that balancing a station is a must in all cases" "easy expandability by just cloning them" | **design** (default unbalanced for single-line entry) |
| S25 | Balance when several incoming lines carry mixed traffic (for example goods and raws share lines to a factory), because the lines cannot all be full. With separate lines per cargo, packing them full makes balancing less useful. | Load per line is below capacity. | ABR07: "When the goods trains split out, the drop receives only raw trains, therefore the lines can't totally be full." | **design** |
| S26 | Pre-signals are the usual entry check. Drops should not need to stop at the entrance. Exception: overflows, which must be able to enter at any time. | Pickup full => refuse. | ABR07: "In terms of pickup stations, there usually are pre-signals to make sure trains don't enter the station when they shouldn't." | **design** |
| S27 | One-way pre-signals are the standard choice for splits and choices (the exit firstred penalty is about 40 000, so trains choose fast). They never divert a lost train, which exposes missing connections. 2-way pre-signals or PBS into 2-way signals choose reliably but let lost trains wander (through some ro-ro station). | Signal penalties. | MT: "One-way pre-signals are always the best option as they make trains choose their path quickly and easily" "2-way signals can cause trains to get lost" | **check** (entry split signals = one-way pre-signals by default) |
| S28 | PBS into 1-way signals chooses badly ("some choices can seem to be ignored"). PBS must lead into 2-way signals. A PBS/prio entry signal sees the prio state, so trains seek the emptier line, but each choice then has very low throughput. Only for main-station exits or SLHs. | Low signal penalty with PBS. | MT: "PBS into 1-way signals is bad" (image caption), "PBS needs 2-way signals to choose well"; "the throughput of each choice gets to be very low so it is only affordable on main station exits or SLHs." IMG: `Mergers_Split_PBS1.png`, `Mergers_Split_PBS2.png` | **check** (no PBS-to-1-way entry) |
| S29 | The best split gives all choices from one first split (one tile). A high-throughput choice split needs aggressive signalling or double bridges; double bridges allow evil mode and slow the "realisation". | The first split decides speed. | MT: "The best option is to have all choices available at the first split." "Splitting all from one tile is fastest." | **design** (entry: unified first split where possible) |
| S30 | Waiting bays must not block access to the other choices. A stopped train must not block the alternative lines. | Trains should be able to choose a different line when one is full. | MT: "we need to make sure that stopped (waiting) trains do not block the access to the other choices" | **check** |
| S31 | The "pre-signal bypass" (a bypass long enough to hold trains) blocks anyway and "doesn't do all that much wonders". | Fills up. | ABR07: "if it is long enough to accommodate trains inside, it blocks" | **design** (do not generate pre-signal bypass entries) |
| S32 | Signal-gap tuning at the entry: a deliberately long signal gap caps throughput of a branch, so that part needs fewer platforms. Penalties on the faster tracks make trains use the slower ones only when needed ("valhallasw style"). | Controls where trains choose to go. | ABR07: "Just by making a longer signal gap, you can cap the maximum throughput of that piece." | **param** (optional) |
| S33 | Full-speed waiting bays: with very small signal gaps behind pre-signals, trains skip to another choice when one is full and keep a full stream. No platform distribution tuning then needed. | Short gaps react fast. | ABR07: "If you can make as tiny signal gaps behind pre-signals as possible, trains could go through one of the choices in their full stream." IMG: `abr/images/ABR07_fastbay_01.png` | **design** (preferred buffered style) |
| S34 | Big splits: a long pre-signal array reacts slowly, so split in halves first (6 platforms = split 2, then 3 each), with the first split's gaps long enough that the later ones do not matter. | Slow late gaps only matter if trains depend on them. | ABR07: "if you need to split one line into 6 platforms, you can first split in half, then each line goes to 3" | **design** (binary tree split for platform count > 3; implied threshold) |
| S35 | Logic splitters (flip-flop) for even distribution are used rarely and judged overkill when a proper entrance would do. "logic should be used when needed, not whenever possible". Refit stations did use a flip-flop 1->6 entrance. | Complexity. | ABR07: "logic should be used when needed, not whenever possible." ABR11: "flipflops to spread the traffic evenly in any situation as 1->6" | **gap** (out of scope for first generator) |
| S36 | Fail-safe unblocker: when two trains can meet on a direct path (several incoming lines, or a non-stop terminus), a signal that turns green only when the train is in front of it lets the train bail into the nearest free block, so it stops in a safe place and not on the main line. | Trains should not stall on the input line. | ABR07: "make them stop in safe locations, not blocking or slowing the main line" "The fail-safe mechanism is NOT supposed to prevent trains from stopping completely!" IMG: `abr/images/ABR07_failsafe.png` | **design** (needed for multi-line direct entry; length of the train matters, TL) |
| S37 | Where trains from several incoming lines meet at one signal block, only one passes; the other blocks for a while. Fixed with proper waiting bays. | One block, two trains. | ABR07: "When multiple trains enter multiple areas which lead to one signal block, only one of them can follow at a time." | **check** (no two entry paths share a block without a bay) |
| S38 | Pre-balanced ro-ro entry as seen in `Pre_balanced_roro.PNG`: a parallel line pair splits into several branch pairs that fan out to platform groups, with each branch having its own pre-signal pair. Two bundles of 5 platforms. | Illustration of unified split to staggered platforms. | IMG: `Pre_balanced_roro.PNG` (viewed). | **design** (shape reference) |
| S39 | Station entry load-balancer with 3 crossings (labelled A, B, C), 2 tiles for braking, one line entering. Shows a balanced entry for one line into 3 platform pairs. | Balanced entry. | IMG: `Station_entry_load-balancer.png` (viewed). Caption on image: "2 tiles for braking". | **design** (shape reference) |

## 4. Exit

| ID | Rule | Why | Source | Generator impact |
|---|---|---|---|---|
| S40 | Exit "balancing" means only that trains have a choice of line; the goal is just to let trains leave "by any means". It does not produce equal traffic: trains fill one line first and then the next. | Priorities check for space, not for equality. | ABR07: "The only thing we actually want is just to let trains leave the station. By any means." "it usually ends up like they fill one line first then move onto another." | **design** |
| S41 | A simple, sufficient exit is "every Xth platform joins one of the X lines". Take care how the entry split penalises platforms: if some platforms are used more, assign exits to match. | Stable and simple. | ABR07: "in most cases I think it is way enough to make it just like 'every Xth platform joins one of the X lines'" | **design** (default exit = fixed platform-to-line mapping) |
| S42 | Station exit merges: trains join each output line at only one spot. Avoid a chain of fully prioritised joins (downstream starve). A short prio at station exits is common because exits have many lines out and the design is simple and repeatable. | Starvation versus fairness. | MT: "The best and most powerful result is to have trains join at only one (possibly prioritized) spot." "Sequence – small priority: ... Often used at station exits" | **design** (exit = small-prio joins; cf. RULES-coop R12, R13, R20-R21) |
| S43 | Do not merge with PBS (see RULES-coop R14); the station-exit merge uses pre-signals and a prio. | PBS merges jam. | ABR03 (via RULES-coop R14): "merging with PBS is B.A.D." Not restated in the station sources. | **check** |
| S44 | Exits do not need to be full-speed to the same extent as the entry, and exit signalling beyond the prio is not discussed. | n/a | not stated | **gap** |

## 5. Termini

| ID | Rule | Why | Source | Generator impact |
|---|---|---|---|---|
| S45 | The "X" in front of a terminus's platforms (entering and leaving trains cross) is the usual problem spot. Its throughput is judged against the platforms behind it: with fast trains and long unloading times the X is faster than the platforms, so a terminus is fine. | Dwell time dominates. | ABR07: "the 'X' has far better throughput than the two platforms behind it, that way, it doesn't matter if the station is terminus or not." | **design** (X terminus acceptable for long-dwell, fast trains) |
| S46 | At the X, pre-signals are usually enough; PBS is not automatically better. Choose by how fast the X must be. | PBS is slower in some setups. | ABR07: "Most of the time the requirements are fulfilled by the seemingly slower pre-signals, therefore PBS doesn't have to be better." | **param** (X signalling = pre-signal default) |
| S47 | PBS terminus image: two parallel lines enter a platform block through a single crossover; a plain, small pair of lines into 3 platforms. | PBS crossing example. | IMG: `Pbs_terminus.jpg` (viewed) | **design** (shape reference) |
| S48 | X-less (non-blocking) terminus: remove the X so entering and leaving trains no longer meet past it. Platforms are then usable as often as in a ro-ro. Each platform has its own in and out path. | Removes the crossing. | ABR07: "The result is that trains in the past X are now not meeting. This means that platforms can be used as frequently as of a ro-ro station." IMG: `Non-blocking_terminus.png` (viewed: each platform has its own bridge or tunnel pair feeding it from the two lines), `abr/images/ABR07_Xless.png` | **design** (terminus with X-less = tunnels/bridges per platform) |
| S49 | Dedicated terminus ("Japan" style): a few long ro-ro-looking platforms where the line splits to the platforms and returns through its own loop. See image. | Separate in and out per platform. | IMG: `Dedicated_terminus_2p.PNG` (viewed: a 2-platform terminus with a looped return and a small tunnel near the entry), `Dedicated_terminus_japan.PNG` (not viewed) | **design** |
| S50 | A non-stop terminus has leaving trains that may meet entering ones, so the fail-safe unblocker (S36) applies. | Trains meet. | ABR07: "Mainly when making a non-stop terminus station (leaving train could meet the entering)" | **check** |
| S51 | Refit stations with a terminus put depots "invisible" (behind), safer against lost trains looping into the station. | A terminus has fewer wandering lost trains. | ABR11: "the station is a terminus, which is a bit more safe from lost trains getting looped in the station." | **gap** (refit only) |

## 6. Self-regulating stations (ABR09, ABR13)

| ID | Rule | Why | Source | Generator impact |
|---|---|---|---|---|
| S52 | Problem: self-regulating networks (SRNW) keep trains full by having dummy trains load the cargo at the industry and transfer it to arriving network trains, so that only full trains leave. Old synchronized designs release all trains together, creating waves, and they cap throughput through platform count and the 64-tile station spread. | Waves jam the exit; spread limits dummy loading. | ABR09: "because the trains are all released at one time, the more platforms, the larger wave of trains." ABR13: "train wave formation ... and station spread (maximum station spread and train length is both 64 tiles long)" | **gap** |
| S53 | Mechanism in one paragraph: a **synchronized** SRNW station has a dummy train that loads, moves a short distance to trigger a NOT gate (or reserves a PBS path), and unloads again, which releases the waiting real trains together. Dummies and real trains must load at different times or they steal each other's cargo. An **asynchronous** one is a **transfer station**: feeder trains drop cargo at a separate drop platform, and a loading train is released only when the feeder is arriving (plus a delayer), nothing blocks the release, a loading train is waiting, and there is a free platform. Dummy-loader pickup and transfer must be separate stations to avoid cargo stealing. | Different cargo timing; one cargo owner per station. | ABR09: "The reason why trains need to be synchronized is because we need to separate the times when dummy trains are loading, and when real trains are loading" "1. Feeder coming? 2. Delayer 3. Train at X? 4. Is there anyone to load? 5. Is there a free platform?" ABR13: "this forces you to use a separate pickup and transfer station" "transfer stations are generally asynchronous by design" | **gap** (logic-gate station; not in generator scope) |
| S54 | Practical limits: platforms and bays need at least 1 TL (the waiting area can be shortened with a NOT gate); transfer stations are slow and have a big footprint, so build several parts. In PBS designs the network trains' exit tracks must be free of PBS-reservable tracks. | Logic needs space and time. | ABR09: "all of those bays/platforms need to be at least 1TL long" "the station performs quite slowly, so it would be very good to make multiple stations". ABR13: "the exit tracks for the network trains must be free of PBS reservable tracks" | **gap** |
| S55 | Both articles advise simplicity and reliability over complexity. | Logic stations are 99% of the work. | ABR13: "a clear trend is visible with simplicity over complexity and reliability" | **design** (exclude from v1) |

## 7. Refit stations (ABR11)

| ID | Rule | Why | Source | Generator impact |
|---|---|---|---|---|
| S56 | Problem: a refit station drops one cargo, refits, picks up another, and refits back to the primary cargo in depots after the platforms. Entry must spread trains evenly so depots do not stack, and trains that load too little should not refit back and lose cargo. | Depots stack under jams; a partial load is lost. | ABR11: "the old design sometimes stacked trains in few depots in case of any problem or jam at the exit." "trains just refit back to primary cargo while being for example 10% loaded." | **gap** |
| S57 | Mechanisms: (a) flip-flop entrance "1->6" to spread evenly; (b) cargo return: under-loaded trains transfer cargo back to the pickup station before refitting back (extra platforms or a separate station); (c) the "TL+1 station": pickup one tile longer, trains stop at the near end, a conditional order decides, and if under-loaded they go to the middle/far end and transfer back; (d) stack-proof depots: depot trains have prio over new trains (prio version), or (ro-ro version) a series of pre-signals plus one combo signal so the waiting train blocks until the depot train has left, and an exit behind the depot so trains wait if there is no way out. | Avoid stacking and lost cargo. | ABR11: "they first transfered the cargo back to the pickup station not to waste it"; "Therefore the TL+1 station was introduced."; "stack-proof depots ... the depot trains have prio over new trains coming to the station." | **gap** (v1 excludes refit; but "stack-proof depot" is reusable for overflow) |

## 8. Signals in stations

| ID | Rule | Why | Source | Generator impact |
|---|---|---|---|---|
| S58 | Signal types by place: entry check = pre-signal (usually one-way); platform choice = one-way pre-signals (2-way only when needed); X of terminus = pre-signals by default; PBS only where justified (S28, S46); no PBS at merges (S43). | See S26-S28, S46. | ABR07, MT (quotes above). | **param** (signal type set per zone) |
| S59 | Entry check: the entry signal in front of the station lets trains in only if there is space. Especially for pickups. | Prevents a full station blocking the line. | ABR07: "The entry signal in front of the station that allows trains to get inside only if there is space for them." | **design** (pickup entry signal = check) |
| S60 | Braking space: keep trains at least one TL between the main/incoming line and the platform. A full-TL braking space is ideal, shorter ones also help. Requirement grows with TL, acceleration, speed and with how much traffic that exact line carries. | The first rule is not to slow the rest of the trains. | ABR07: "First rule should be that we need to keep trains at least one TL from the main line and platform." "A full TL braking space is an ideal case, but any other braking space can be useful too" | **param** (braking space = TL by default; see S61) |
| S61 | Braking space per split level: platforms joining directly from the main line need full braking space (1x TL). After a split into two arrays, the first array (from the first entry signal) needs a full TL, and the second, with half the trains and farther from the main split, needs less. Braking spaces also help keep stress points (the X) fast. | Traffic per branch and distance from the main line. | ABR07: "we require full braking spaces (1x TL)" "the other array is expected to have only ~half amount of trains" IMG: `abr/images/ABR07_braking_03.png` (viewed) | **design** (first-level = TL, deeper levels shorter; no formula; "~half" only) |
| S62 | Signal gap = array of missing signals. Too long a gap (for example a long pre-signal array in one block) makes pre-signals react slowly and caps throughput. | Slow reaction. | ABR07: "The longer this station is, the slower the pre-signals will be, thus making packed line throughput impossible." | **check** (limit gap length; no number given) |
| S63 | Signal spacing is never given in tiles. The stated spacing quantity is "TL" for bays and the "3 tiles where trains stop" at TL3. | n/a | not stated numerically | **gap** |

## What the sources don't say

- No formula or table for platform count versus traffic, entry rate or dwell time; only "test it".
- No numeric platform length, waiting-bay length, signal spacing, or gap limit (only TL-based descriptions and the TL3 examples).
- No rule for which side of a line a station hangs, or how a station connects to a sideline hub beyond "via a sideline".
- Exit signalling is thin: only "fill one line then the next" and "small prio at station exits".
- The content of the Junctionary station sheets (Basic, Pickup, Drop, Combined, Special Case) is not available as text, only 75x75 icons and file names. Several station pages in the coop wiki (full-text) are not in the local archive.
- Behaviour of a ro-ro with all-to-all balanced entry (`Roro_all-to-all.PNG`, `Roro_all_to_all_pz05.PNG`, `Roro_dedicated_plats.PNG`) is shown in images I did not view, so no rule is cited from them.
- No guidance on mixing different train lengths at one station (RS says to avoid different lengths).
- ABR05 (S-Bahn) covers orders and catchment, not station layout; ABR06/ABR10 contribute nothing beyond the merger and balancer material already used in RULES-coop.

## Open questions for the engineer

1. First target: pickup, drop or both, and ro-ro only or also terminus (X-less)? (I recommend ro-ro drop, 1 incoming line, no balancing, as v1.)
2. Platform count: a user input, or should the generator derive it from a train-per-hour estimate (the sources give no formula, so we would need our own, perhaps from simulation)?
3. Platform length: exactly TL, or TL plus a braking tile inside the platform block?
4. Entry: should v1 be buffered (full-speed waiting bays) or direct (synced) or both?
5. Balanced multi-line entries: in scope for v1, or later (the XeryusTC style is "hardest")?
6. Are we allowed to derive our own numbers (braking space for deeper split levels, signal gap limit) by in-game rig tests, as with the junction prio lengths?
7. Which traffic model do we test stations against: the junction rig's trains, or new pickup/drop order sets with load times?
8. Station connection: does the generator emit the station plus its own sideline entry, or take a given sideline end point and a free area?
