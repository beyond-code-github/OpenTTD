# RECON: the new projection pipeline behind the in-game hover (read-only; 2026-11-12)

Paths are under src/ unless noted. INFERRED = not read in code. PROPOSED = my design.

## 1. What the hover does today
- Window `BuildJunctionWindow` (junction_gui.cpp:309). Mouse-over (gui:1085-1098): tile change -> `ShowHover()`; after `JUNCTION_HOVER_REST` 300 ms (gui:313) with no cache hit -> `StartJob()`.
- `ShowHover` (gui:540): cache hit -> `ShowResult`; else the "instant tier": `MakeJunctionTerrain(hover_tile, rot, mirror, frame, 4)` on the main thread then `FitJunctionLibraryNear` (gui:553-560, game:~520). Needs a picked train, sizing done (`SizingStatus` gui:458), library built (`LibraryUsable`), ml_gap != 0.
- Job model (gui:640-690): one `std::thread` via `StartNewThread` per hover spot, owns a main-thread snapshot (`job->terrain`, margin 4), runs `GenerateJunctionNear` (game:442) = ring offsets {0,2,4,6,8} (`JunctionNearOffsets` game:~420), each runs `SearchJunctionNodes(topo.layout, spec, shifted, start_offset, 16)` on `JunctionNodeTopologyT()` (game:447, 473), then `FitJunctionLibraryNear`, best of the two. `done` atomic polled by `PollJob` (gui:696) -> `StoreCached` (32 entries, `MAX_JUNCTION_CACHE` gui:312). Cancel is a flag; a stale job finishes and is ignored (gui:653).
- Result: `JunctionNearResult{JunctionGenerateResult{layout, error, hub, score, prio_tiles}, offset}` (game.h:79). Layout = `JunctionLayout{size, tracks, signals, bridges, stations}` (layout.h:58): per tile TrackBits, NO per-tile level, bridge `z` only for tunnels (layout.h:46).
- Ghost: `ShowResult` (gui:572-630) rotates the layout (`ApplyJunctionOrientation`), computes origin = hover tile + near offset - `OrientJunctionOffset(hub, size, rot, mirror)`, `ComputePlacement` -> `EstimateJunction` (layout.cpp:321) + `ChooseJunctionBridgeType`, then `JunctionGhost::Set(layout, origin, estimate.height, railtype, bridge_types, estimate)` (gui.h:45, ghost impl gui:91). Ghost draws per-tile TrackBits/signals/bridge heads/spans via junction_ghost_draw.cpp; bridge deck z = (height+1)*TILE_HEIGHT from ONE reference plane (gui:143).
- Build: `StartBuild` (gui:~950-990) -> `MakeJunctionBuildSteps(layout, origin)` (layout.cpp:282: stations, rail per Track, bridges, signals) -> `GetJunctionSequencer().Start`; `OnRealtimeTick` ticks `GameJunctionStepPoster` (game:553: BuildRail, BuildRailStation, BuildBridge/BuildTunnel, BuildSignal). Shift-click only shows the estimate.
- Cost shown: `estimate.total` in tooltip and WID_BJ_COST (gui:615-630); `EstimateJunction` marks any tile not in ONE plane H bad (layout.cpp:346-368): it cannot price a terraformed junction as is.

## 2. The frame
- Old: working cell (x,y) = anchor + `OrientJunctionVector({x - frame.hub_x, y}, rot, mirror)` (game:351-383); anchor = hovered tile; `JunctionFrame` 64 wide, terrain 43 rows from y=-2 (generator.h:82); rotation is a window static `_junction_rotation` (gui:274), mirror `EffectiveMirror()` (gui:366), R key / mirror hotkey (gui:809, 1103). Terrain cells carry canonical slope and incline (`JunctionCanonicalSlope` game:~270); `Rect` variant `MakeJunctionTerrainRect` (game:386) is rotation 0 map-axis.
- New: the placement frame is box tile (0,0) = north-west, x east, y south (topology.h:243); `offset` = snapshot tile of placement (0,0); the box is `seed.placement.size`/`seed_layout.size`. The test centres the box in the snapshot (real_terrain.cpp:120). The terrain origin/width come from `terrain.origin` (negative allowed).
- PROPOSED mapping: build a `JunctionFrame{hub_x = size.x/2, terrain_origin_y = 0, terrain_height = size.y, width = size.x}` for the seed box, call `MakeJunctionTerrain(hover_tile, rot, mirror, frame, 8)`; then `offset = {-8 - ?, ...}` is simply terrain.origin + margin, i.e. offset = {terrain.origin.x + 8, terrain.origin.y + 8}, so the box centre column sits on the cursor. The size must be the seed's (placement may differ in size by the solve: INFERRED, tests centre on seed size and succeed on 18 fixtures, real_terrain.cpp:120-127). "Near offsets": D197 says cursor spot first; the new path needs only offset (0,0) and the placement search already moves things inside the margin (INFERRED); fall back to the old ring only if refused.
- Topology: the GUI uses ONLY the T, via `JunctionNodeTopologyT()` (game:447, generator:1958). No topology picker exists (grep of "Topolog" in junction_gui.cpp: nothing). `JunctionTTopology()` and `JunctionLLRRSidelineTopology()` exist (topology.h:369, 372) but nothing selects them in the GUI. T5 (DESIGN-G1 §14.7:329) says "topology picker" is part of T5.

## 3. Terraform in game
- Commands exist: `CmdTerraformLand(flags, tile, Slope corners, dir_up)` raises/lowers corner(s) one level and propagates (terraform_cmd.cpp:172); `CmdLevelLand(flags, tile, start_tile, diagonal, LevelMode)` (terraform_cmd.cpp:326). Nothing in junction code posts them (grep: none). Pricing in the snapshot uses `_price[Price::Terraform]` (game:336).
- Plan: `JunctionTerraform::corners` map (x,y) -> target height in the SNAPSHOT canonical frame, corner (x,y) = north corner of snapshot tile (x,y) (terraform.h:21); `Money cost` (terraform.h:23); placement.terraform/height_cost (topology.h:254-255). `ApplyJunctionTerraform` gives the resulting terrain (terraform.h:32).
- PROPOSED plan -> steps in map coords: for each corner, canonical lattice point -> map lattice point with the inverse of `OrientJunctionVector` (the rotation/mirror is linear on lattice points, but a tile's min corner moves: shift by up to one in x or y; this is the one subtle bit), pick the map tile and its `Corner` (W,S,E,N via `TILE_CORNER_OFFSET`, terraform.cpp:25), current height from the live map (`TileHeight` at that lattice, game not snapshot), and post |target - current| `TerraformLand(tile, SlopeWithOneCornerRaised(corner), up)` steps. Order: the plan is already propagation-complete (terraform.h:28), but game propagation can touch a corner already at target if steps go in a bad order; order raises before lowers, or verify with a pure simulator test (below). New step type `JunctionTerraformStep{TileIndex tile; Corner corner; bool up}` in the `JunctionBuildStep` variant (layout.h:78) + a case in `GameJunctionStepPoster::Post` (game:553). Steps come BEFORE rail steps.
- Ghost: no drawing of planned heights exists (ghost_draw has only track/signal/bridge, ghost_draw.cpp). The ghost draws tracks at the tile's current slope. PROPOSED minimum: do not draw terraform; mark terraformed tiles (corner set tiles) with the existing `bad`-style tile highlight or a tile-selection rect (`DrawTileSelectionRect` ghost_draw.h:31) in a distinct palette, and show the cost. Drawing the raised ground is later work (a custom `DrawTile` hook), not needed for the first hover check. Bridge span z: with terraform the single-plane `height` is wrong; INFERRED the new layout needs a per-bridge z from the levels (bridge heads are tile levels; `JunctionBridge` has no z for bridges, layout.h:46).
- Cost to the player: terraform `plan.cost` is inside `placement.height_cost` (also foundations and clearing, topology.h:255). Total = height_cost + rail/signal/bridge price. Today `EstimateJunction` would price rail with the plane check; PROPOSED `EstimateJunctionTerraformed(layout, origin, pricing, height_cost)` that skips the plane check (the layout pieces are valid on the planned ground by the solve) and adds `height_cost`, keeping bridge pricing via `ChooseJunctionBridgeType`.

## 5. Risks
- Threading: topologies are function-local statics (topology.cpp:3729, 3746) -> init is thread-safe. Grep of junction_topology.cpp, junction_levels.cpp, junction_terraform.cpp, junction_facts.cpp for mutable statics found only function-local caches (`bend_rasters`, `half_cache`, topology.cpp:1611, 1699: local variables, not static): no shared cache found; INFERRED thread-safe so long as each job owns its seed copy or reads a const shared one. The seed's `topology` pointer is to a static const: fine. The game's `_price`, `_settings_game` are read ONLY in `SetJunctionTerrainSettings` (game:336), which stays on the main thread in snapshot (as now, gui:658). `Command<>::Post` stays on the main tick.
- Timing: your measured numbers (seed ~2 ms cached per spec, placement ~1 ms, levels ~7 ms mean) fit < 100 ms on one thread if the seed is cached per spec; the snapshot is built on the main thread: 80 x 40 cells (3200) of `FillJunctionTerrainCell` incl. `QueryJunctionClear` (a command test run per tile, game:~300) is the unmeasured cost: the old path logs it (gui:559-562 Debug2); INFERRED worth measuring; margin 8 vs 4 means roughly 2x tiles of the old snapshot (old 72x51 at margin 4 = 3672: similar).
- Snapshot size: levels need the box + margin 8 (RECON-joint-levels, by your brief); fixtures are 80 x 40 so a T box of about 64 wide needs margin >= 8 on y: the old frame's terrain rows are only 43, so a new frame is required (section 2), not `MakeJunctionFrame(spec)`.
- D219: `SizingStatus` already refuses with `STR_JUNCTION_ERROR_NEEDS_REALISTIC` before generating when the model is Original (gui:465). `JunctionRampLevels(spec)` (generator:108) uses the realistic train params; the new path must keep this gate (same `SizingStatus` call) and use `spec.prio_tiles` from the sizing (the seed depends on it: INFERRED, so seed cache key = `SpecKey`).
- Failure modes to surface in `hover_status`: placement empty (`why` text: "terraform conflict ...", class facts), levels fail (17 of 18 fixtures solve): show the status string and fall back to the old path or no ghost; never a silent worse layout (memory: no silent shortcuts).
- The terraform step order and the game's own propagation could differ from `PropagateJunctionTerraform`: the plan's `cost` may differ from the game's quoted cost. Check with a `DoCommandFlags::None` (test-run) of the steps on a live map before building (or compare totals in the first in-game run).
- Bridges over terraformed ground: bridge pricing and the ghost span z need the solved level, which the layout does not carry (layout.h:46): needs the levels' per-tile result exposed (or recomputed from `ApplyJunctionTerraform` + head tile z).
- Build-time state: terraform changes the map; the old `OnRealtimeTick` Done path clears the cache (gui:1003-1008); the failure path (`Failed`, Retry) rebuilds a ghost from `build_layout` and has no knowledge of terraform: a failed terraform step must pause with Retry/Cancel like rail steps (sequencer is generic over steps).
