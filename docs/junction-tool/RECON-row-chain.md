# RECON: a general row chain for placement (DESIGN-G1 §14.6, §14.7 T4a, §15)

Read-only recon; code is src/junction_topology.cpp (J) unless noted. Claims are read; INFERRED marks what was not read. PROPOSED marks design.

## 0. Where rows are special today
- Programs: ProgramJunctionTrackGraph refuses any row that is not exactly in + one leg + out (row_total/in_count/leg_count/out_count, J:731-743, error J:742). A row edge gets: leg of an undoubled row = empty program (J:785); doubled leg = [Over.., SBend] and copy 1 [SBend, Over..] (J:788-794); in edge = [Fan(north_item or lane_item)] (J:796-799); out edge = [Fan(lane_item)] (J:800-803). A crossed in or out edge is refused (J:763). An edge between two row nodes is refused (J:727).
- Placement: PlaceTrackGraph builds `chain` (Elem lists) ONLY for non-row edges (J:1035 `if (is_row_edge(e)) continue`); row edges live in `row_pts` (J:1305-1320) with fixed members: fif, fil, fof, fol (in/out fan first/last), lane_split, sb1_last, sb0_first, lane_merge, and per bridge k nh0/fh0/nh1/fh1.
- Render is already generic (see §2).

## 1. Every in/leg/out assumption, and what a general chain needs
1. Shape check, J:731-743 (programs) and J:975-990 (placement: in_edge/leg_edge/out_edge arrays, error J:989). Need: any number of row edges per row; edge roles by position in the row, not by in/leg/out. (A row is in-edge, [nodes and legs]*, out-edge; the graph already has one edge per consecutive pair, so "several legs per row" is just several row edges.)
2. `doubled_row(r)` = leg_edge[r] has a doubled bridge (J:993); `row_doubled` in programs (J:769-777). Need: doubledness per edge (it is already per edge in structure.bridges); a row with two doubled legs would need two copy-row stretches. INFERRED: north_item (copy row) then belongs to a stretch, not to the row.
3. lane_item / north_item (J:960-968, programs J:708-715): one copy row per row, "the stack item just north of the Lane item". Used as y of: exit split nex (eq J:1941), njm (J:1942), lane_split/sb1_last/heads/sb0_first/lane_merge (J:1947-1960), y_exit/y_lane in occupancy (J:1683-1697), facts (J:2476-2490), sym_routes (J:1433-1434), tiles_under (J:2857). Need: a y per element from the token's stack item (the Elem `index` already does `eq(1, el.last, item_pt[el.index])`, J:2104-2112); Shift needs new stack items (structure change, §4 step 4).
4. Fans: `fan_item(e)` = program is exactly [Fan] (J:1236 region; used J:1310-1316, best_offset/set_port_rows J:2573-2593); size fan_m[e] = |port_row - item row| (J:2591), no Elem. Rows: fif = port-row point where the fan starts (y = port_row), fil = item-row end; m=0 collapses both onto the port (J:1944-1950 `eq(0, fif, pin, 0)`). Need: a Fan kind whose size comes from port_row/offset (a choice, `choices.port_offset`), which can be empty, and which may be followed by more tokens (today a program with more than one token is not a "fan edge": fan_item would return NO_ROW and the fan would be lost).
5. In-edge run relations: `along(heading, rp.fif, pin, 2, false)`, `fil = fif + m-1` exact, `nex >= fil + 2` (J:1964-1975); out edge `fof >= njm + 2`, `fol = fof + m-1`, `pout = fol + 2` exact (J:2038-2050). Constants 2 and the exact port stub belong to element pairs (Fan-after-port, last-bend-before-port). Need: a floor table keyed by (previous element kind, next element kind), as `chain run` already is (J:2127-2137, dist = 2 flat).
6. Prio element: not an element, two relations on a row: undoubled `njm >= nex + even_prio + 1`; doubled `njm >= lane_merge + even_prio + 2` (J:1976-2002). The signal pass draws it from the merge node and the joiner (J:3232-3300), independent of row shape. Need: a node-attached "prio coverage before" floor on the run that enters an ML-merge node, whatever token precedes (so +1 after a bend, per RECON-prio-element §3-4 as quoted at J:1999). INFERRED: a Shift in the covered stretch (even_prio upstream of the merge) must be refused, as the element's row must be clear.
7. Doubled leg: copy 0 SBend (sb0_first..lane_merge) and copy 1 SBend (lane_split..sb1_last), copy1 heads = copy0 heads + u, stagger (J:1983-2010); `bend` span built from `std::abs(y_lane - y_exit)` (J:1433, J:1694) i.e. multi-row S-bends are sized by item distance, whereas Elem horizontal SBends move one row (`eq(1, last, first, VY[side])`, J:2110-2111). Need: Elem horizontal SBend sized by the item rows (row distance), and copies as two chains with a join (§4).
8. Heads: row heads are four points per bridge (nh0, fh0, nh1, fh1); the Elem `Heads` kind is two points and, in chains, only a Y-axis single bridge over an S-bend (J:1075, J:2139-2154 `bridge over S-bend`, error "a bridge over several band crossings is not ruled yet"). `collect_bridges` (J:1828-1854) and `bridges` output (`heads_of`, J:2760-2771) special-case rows by leg_edge/doubled_row.
9. Series bridges: `nh0[k] >= fh0[k-1] + 2` (J:1996) per k; CutJunctionTrackBridges (J:~3545-3600) re-places per cut; it only edits structure.bridges, so it is shape-independent except via the row code above.
10. D215 objective: row_changes (J:1322-1345) are built per row edge by role: in-fan "kind 1 first", out-fan "kind 1 last", leg "kind 3/2" (sb0_first/lane_split), non-row SBends "kind 4" (J:1334-1345, skipped when `programs.copies[e]` non-empty, J:1337). Group roots come from exact two-way relations (J:~1198-1215). Need: every SBend/Fan/Corner token on a row edge becomes a RowChange whose feature = the nearest node/head/port in the token's direction. Kind 4's rule (before/after emitting tokens) is already generic over a chain.
11. Curves: sym_routes builds row bends specially (J:1424-1449): in-fan (fif), out-fan (fof), doubled SBend; non-row bends come from chain Elems (J:1450-1462). The curve-gap family (J:2179-2222) itself is generic over `SymCurve` (anchor pt, offsets, hand). One horizontal heading per route (J:1525-1531 "two horizontal headings" error): a Shift keeps heading, fine.
12. Y phase: item equalities per element (J:1941-1960); waiting room is node-only (J:2054-2073). x_phase facts for rows (J:2476-2535) mirror the same role list as the occupancy rows block (J:1683-1737).
13. Results: placement.edges[e]/copies[e] spans per TOKEN (J:2780-2830), already general in count (render checks `spans.size() == tokens.size()`, J:2968). Row edges fill spans by role (J:2800-2823): in/out = one fan span, doubled leg = SBend + Over spans.
14. Signal pass: JunctionRouteEvents finds a doubled edge's lane split and merge by the FIRST SBend token of copies[e] and edges[e] (J:3153-3162). A Shift's SBends on a doubled leg would be mistaken for it. Need: tag the role (token field or hand-pair flag) instead of "first SBend". Otherwise the pass reads node pieces at edge boundaries (J:3135-3143) and route tags: shape-independent.

## 2. What Elem chains already do generically; what a row edge would gain
Elem kinds: Tile, Corner, SBend, Heads (J:1028-1043); per element: sizes (refresh J:1243-1252), runs (`chain run`, J:2127-2137), symbolic tiles (edge_tiles J:1360-1380, used for crossers' hug tiles and tiles_under), occupancy occupants (J:1657-1681), facts groups and runs (J:2430-2473), curves (sym_routes), D215 kind 4, Y/X solve, spans per token (J:2820-2858).
A row edge as an Elem chain would gain, per row token: automatic occupancy and facts (row_run/bend_heights/group), edge_tiles for crosser hugging, curve gaps, D215 push, spans and render with no per-role code. The render needs nothing (it walks tokens and spans, J:2953-3090).
No Elem kind yet for: Fan (size from port row, may be empty, starts on a port row not a stack item); doubled-leg copy pair (two chains over a shared stretch, lane split/merge as switch tiles, copy heads staggered); prio coverage (a floor on a node, not an element); bridge head GROUPS on a row (X-axis, several per edge, two copies, hugging crossers, series spacing, middle-limit `spec.max_bridge_middle` check at J:2872-2879); multi-row horizontal S-bend (m from item rows); row-edge Heads over crossers in several non-row edges (Heads has one `cross`, J:1040).

## 3. Relation families: generic vs row-specific
- Generic over Elems (and SymCurve): curve gaps (J:2179), facts groups, run floor `chain run`, tile/occupancy collection for non-row edges, D215 kind 4, y/x of tokens by `index`.
- Generic code but fed row data by hand: occupancy engine (the grouping/ordering J:1741-1800 is generic over Occupants; only the producers differ: non-row chains J:1657-1681 vs the rows block J:1683-1737); facts (`group`/`row_run` generic, rows block hand-listed); curve gaps (rows' bends pushed by hand, J:1424-1449).
- Row-specific: relations of §1 items 5-7 and 9 (row chain constants, prio, doubling, series heads), hug candidates (`hugs`, J:1810-1826, J:2004-2034; the hug itself is generic over a Heads pair and crosser tiles), `collect_bridges`/clearance (J:1828-1880, plan_clearance J:2601), port rows/fans (J:2573-2593), D215 kinds 1-3.
- Clearance (bridge middle) is generic over lines/heads once Heads kinds report their lines.

## 4. PROPOSED design: rows as Elem chains
Principle: one chain per graph edge, row or not; a row edge's program holds any of Fan, Corner(none), SBend, Over, Under. Edits insert tokens into programs; placement walks chains. Row nodes (nex, njm and any new) are Tile elems like band nodes already are (node_of_pt).
New Elem kinds and their relations (PROPOSED):
- `Fan` (SBend with `rows_from = port_row`): start y = port_row of its port (set by `choices.port_offset`, J:2591), end y = its item row; m = |dy| (a variable fixed per state, like fan_m); may be m=0 (then first == last == previous point, as J:1944-1950). Relations: size exact (`2m` halves, `eq(0, last, first, m-1)`), run floor 2 after port (J:1969), D215 push (kind 1), curve gaps via bends, occupancy/facts as SBend.
- Horizontal `SBend` sized by rows (generalise `el.m` for hin horizontal: m = |item_y(index) - y_in|, so a Shift or the doubled lane change of any row distance works). Same relations as today's SBend. This also covers Shift: an S-bend pair on the leg = two SBend tokens (hand +,-) with the shifted stretch between them, or one token when "staying shifted" to the port (D195). Floors: opposite-hand gap >= 2 (JunctionCurveGaps, generic).
- `LaneSplit`/`LaneMerge` (switch tiles of a doubled leg): two chains per doubled edge (programs.edges and programs.copies are already two token lists): copy 0 = [Tile.., Heads.., SBend(sb0_first..lane_merge)], copy 1 = [SBend(lane_split..sb1_last), Heads..]. Join relations: copy 1's SBend first == lane_split on copy 0's straight; copy 0's SBend last == lane_merge on copy 1's straight; `eq` between stretches (J:1983-1990). Occupant copy tags -1/0/1 already exist (J:1659).
- `HeadsPair` (replaces row nh0/fh0/nh1/fh1): near/far heads on copy 0 and copy 1 rows, copy1 = copy0 + u (D118), n <= nmax check, hugs over crossers' edge_tiles(Heads.cross list). Generalise Elem.cross to a bridge index (crossed set from structure.bridges); keep Y-axis single `Heads` as is. Series spacing `>= 2` becomes the Heads-after-Heads floor in the table.
- Node footprint floors, not an Elem: `prio_before(node)` (even_prio+1 after a straight, +2 after a bend), `exit_waiting` already node-only. The floor table (§1.5) moves the constants "2", the port stub, the prio, D145 floors into one table keyed by neighbouring kinds, each citing its rule (D217).
- `Ramp` (§15, later): a vertical token on a horizontal run. Y/X unaffected (a Z variable per run, D218); relations: ramp length per level and floors to curves/switches/signals/other ramps, as new entries in the same floor table; D215 push as a RowChange. A ramp token cannot sit inside a bend (Elem order).

Migration (each step: seeds, spans, choices and tests identical; oracle = [topologysweep], [placeoracle], [topoprojsweep] unchanged):
1. Table of floors: replace the constants at J:1969-2050 by a function floor(prev kind, next kind, node context) with the same values; no structure change. (Seeds identical by construction.)
2. Row-edge Elem chains built in parallel, unused: assert equality of vy/vx for every row point against row_pts (debug check in the sweeps).
3. Fan and in/out edges: switch in/out edges to chains (Fan Elem). Removes fan_item "exactly one token" condition; keeps best_offset. Check: spans, choices.m/corner/port_offset equal.
4. Undoubled legs (empty chain: Tile..Tile between nodes) and the prio floor on the node.
5. Doubled legs: the lane split/merge pair and HeadsPair; drop row_pts, nh0..fh1, `doubled_row`, collect_bridges row half, hugs special-case. Seeds equal on T and LL_RR across tl 3-8 x speeds.
6. Programs: replace the row-shape check with per-edge roles; add role tags to SBend tokens (lane split/merge vs Shift) and fix JunctionRouteEvents (J:3153-3162).
7. Shift edit: insert SBend pair into an edge's program; structure.stack gains a shifted item per Shift (new Lane-kind item or "side" item between existing rows; row gaps stay variables). New tests: a house mid-row on LL_RR builds by a Shift.
8. Ramp token (T6/Z2).

## 5. Risks
- Seeds: the least solution is unique, but point numbering changes (`new_pt` order, J:1007-1013, 1305) and `x_floors` use ids (J:2871 test, columns J:2580); the D215 objective's `most`/`group` iteration is keyed by point ids and `row_changes` order (J:1322, ~1198-1215), so ties in "pushed" order could change results; keep allocation order or sort by a stable key and compare placements in the sweeps.
- Objective: kinds 1-3 are hand-ordered ("edges ascending, an edge's tokens ascending, copies after", J:1322); turning rows into chains must reproduce that order exactly; kind 4 skips edges with copies (J:1337), rows would need the same skip.
- Timing: more Elems per row means more occupants and curve-gap pairs (JunctionCurveGaps is all-pairs per route, J:2181); today ~0.5 ms/state (DESIGN-G1 §14.6); each Shift adds 2 bends per route through that row. Measure at step 5 and 7 (hover target < 100 ms).
- Signals: JunctionRouteEvents' "first SBend" lane-split lookup (J:3153), SignalJunctionTrackRoutes phase 0 prio geometry (J:3232+) read tags (edge, copy, token); inserting tokens shifts token numbers: tags carry token indices (render J:2943-2963, 3040-3047), so event lookup by index changes. Role tags fix it.
- Render: generic; risk is only multi-match of bends (`matches != 1`, J:3021) for two adjacent Shift bends and for Fan with both hands tried (J:3007-3010): a Fan followed by an SBend token of equal geometry may be ambiguous.
- Tests: pinned programs (src/tests/junction_topology.cpp:373-417) stay valid (no new tokens in seeds); tests reading `programs.edges[e].size()==1 && Fan` (J tests :1236, :1304, :3191) rely on the fan shape.
- Occupancy "legal group" test uses reference ties (`ref_shares`, J:1760): a Shift near another line creates new shared-tile groups; the reference is the flat seed (no Shift), so the legal-ties rule needs the cached root (D217 already notes it, J:1760 comment).
- Facts: D214.4 "a run covers its whole row to its next change" is exactly what a Shift relaxes; the per-run domain code (`row_run`, J:2306) is reused once rows are chains, but x-domain of a bend token on a row must include its half tiles (bend_heights, generic).
- Stack: a Shift needs a stack item or row gap per shifted line (structure.stack, J:1890-1896 `stack rows` eq/ge); band gaps (J:1898-1905) refer to row_first/row_last, which a shifted item changes.
