## Method

- One headless run per save (SV1 recipe, scratch config, 5 ticks); a game_start.scr issued `map_export` for every 256x256 box up to 4096x4096 (boxes outside the map are ignored by the command). 178 saves, each under 1 s; none skipped. Empty boxes deleted, JSON compacted (1.1 GB total).
- `find_hubs.py` (python3 -I): 40x40 windows, step 8, over the rail bounding box of each save. A window is dropped if any station tile lies inside it or within 4 tiles.
- Border crossings: a rail track on a border tile whose edge leaves the window and whose outside neighbour has a track on the matching edge, or a bridge/tunnel head whose far end is outside. Adjacent crossings on one side form a bundle (tracks per bundle = crossings in it).
- Added to the brief: tracks are joined into connected clusters inside the window (tracks sharing a tile edge, matching neighbour edges, bridge/tunnel head to far head, bundles that touch). A candidate is one cluster, so two unconnected parallel lines do not count as a hub. Switch tiles, bridge heads and signals are counted over that cluster only.
- Switch tile = tile with 2+ track bits that are not exactly Upper+Lower or Left+Right (so X+Y crossings count). Signals = signal records on the cluster. Score = switches + 3 x rail bridge heads + signals.
- Deviation: clusters with more than 5 bundles are skipped. With no cap the top 3 of every save were 8-to-17-bundle meshes (a first run with a cap of 8 gave 529 candidates, only 17 with 4 or fewer bundles). Cap 5 keeps 3-, 4- and 5-line hubs.
- Overlapping windows merged greedily by score; top 3 per save kept. Per-hub JSON is a crop of the stored export to the cluster bounding box plus 6 tiles (same content as a re-run of `map_export` on that box; no second game run). ASCII: rows = map y, columns = map x (not screen orientation).
