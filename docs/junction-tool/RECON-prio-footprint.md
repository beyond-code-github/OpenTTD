## 1. How PlacePrio chooses and lays
- Per ML merge (non-first event of an ML path), GeometryOfPrio (:278-302) returns nothing, and PlacePrio returns true having added nothing (:313), when: merge piece not diagonal-axis (:285), no joiner (:289), joiner is a lane merge (same from/to), joiner_index == 0, or the joiner's previous tile is on the merge's row (offset == 0, :296).
- Side: the joiner's previous tile lies at offset o across the axis; side = the edge whose step across the axis is opposite (o<0 gives +1, else -1) (:297-301). One side, no sweep (D75, D87). h1 = corner(side, exit_edge) on the ML tile; h2 = corner(reverse side, reverse exit) on the row tile.
- Row: the single tile row across = merge across + side. Row tile at step s (s tiles upstream) = merge - s*dir + side_diff (:392).
- Joins: step 0 (merge tile), plus in every ML block "required" by the coverage walk (:332-348): from the merge back along every lane of the movement while covered < 2p units (one tile = 2u, so p tiles on a straight; diagonal halves 1u each), plus the block of the piece one beyond (D107, :346). In each required block the join is the nearest-to-merge ML tile that has no signal and holds the axis alone with an empty side neighbour (or an already reserved join, :361-366).
- Lays (:409-445): merge tile gets h1; join tiles h1; row = h2 alone at step 0, axis+h2 at joins, axis between, up to the farthest join (S = max step). One signal on the row tile beside the downstream join of each consecutive pair (Combo, last one Exit, facing upstream).
- Returns false (the prio is abandoned, phase 0 reservation undone, checker later says "missing prio"): merge tile has no block (:325); a required block that has a joinable tile but none usable (:381); a join not on the merge's row (:389) or at step <= 0 (:391); any row tile already holding tracks other than what the prio would lay (:402); two joins adjacent (:408, signal needs a tile between). It never checks edge contact: a foreign track touching the row is found only by CheckPrio step 2.
- Phase 0 (ReservePrioJoins :457) pre-lays one join per lane-merge block inside a later merge's coverage, only if the ML tile is axis-only and the side tile empty.

## 2. The footprint, per prio merge (merge tile M = (xm, ym), ML direction d = exit edge, side n, along coordinate a)
Let S = farthest join step (0 <= S <= p+1 on a straight; the +1 is D107's piece beyond the coverage).
1. Row R = ym + n (x-axis ML) or xm + n (y-axis). Tiles (a = am - s*d, s = 0..S) on R hold only the prio: h2 at s=0, axis (+h2 at joins) elsewhere. They must be free of every other track and signal (:402 plus CheckPrio "prio tile holds tracks other than the axis and a join").
2. ML tiles at steps 0..S need not be reserved beyond what the ML already is, but each join tile (s>0) must be an axis-only, unsigned ML tile (the h1 half piece makes it signal-illegal); every required block within the coverage needs at least one such tile whose side neighbour is on R's free stretch (:361).
3. The joiner is NOT part of the prio. It approaches the merge tile from the opposite side (-n) and its piece sits inside M (CheckPrio :1155 adds the joiner's track to M's expected bits). Its run is on the far side: today's W prio is on row 3, N->W's run is on row 5, the ML on row 4.
4. Edge contact (CheckPrio step 2, :1243-1263): no unused prio track may touch a foreign track's facing edge except the join contacts (h1 at the exit edge, the merge's joiner). Concretely: tile at s=S+1 on R must hold nothing touching its edge toward the prio (a track reaching the facing edge of the axis end). Tile at s=-1 on R (downstream of M): h2 does not touch the exit edge, so no condition. Axis and h2 touch only the upstream/downstream edges and the ML-side edge, so nothing on the far side of R can touch it; Y runs and diagonals that cross R inside [0, S] are overlaps, not contacts.
5. Straightness: D111 allows bending prios, but PlacePrio (:389) and CheckPrio (single row, :1205) do not. The footprint is a straight row today.
6. No ML split of any kind in the coverage plus one segment (G9c, D108) and no bridge head in it (PrioReach residual): a T3 condition, not occupancy.
Reserve-the-bound form: R, a in [am - (p+1)*d, am], plus the contact tile at am - (p+2)*d. Exact S needs the ML's block structure (signals), which the template does not have; the bound is derived from the coverage walk, not padded.

## 4. Mapping onto DESIGN-N3 section 7
- The prio row is a free X run on a current row (R = ML row +- 1, which may coincide with another line's row: W row 3 is also lane A's row at x 30..40). In the chain it is one element: flat lo = xm - (p+1) (class of M minus a constant), hi = xm, owner set empty (its own, nothing to share), same row as foreign elements, so the overlap failure and gap rule apply: gap 2 to a neighbour whose track reaches the facing edge across the end (the contact tile above), else 1.
- The join pieces (h1 on the ML tile, h2 + axis on R at joins) are inside the footprint or on the ML, so they add no elements; M's h1/joiner are a switch-tile group (equal-x group) already.
- Where it does not fit: (1) the far end is not a class value; S depends on the ML's signals/blocks, so the chain would use the bound p+1, which can over-reserve by up to p tiles of row when joins sit nearer; (2) the side n comes from the joiner's approach, known from the turn programs but not from a node-local class, so it must be input to the template; (3) the chain's elements are per current row, while the footprint is created after the Y snap in rows whose index is ML row +- 1: fine since the ML row is known; (4) vertical contact is not needed (axis never touches N/S edges); (5) the required free-ML-tile-per-block condition and G9c/PrioReach are 1-D ML conditions (T3), not row occupancy.
