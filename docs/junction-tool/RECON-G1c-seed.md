## 1. Position-derived constants in the template builder

Common mechanism. `tpl.flat[c]` is the tile coordinate of the FIRST point (in first-appearance order) of class c (:273, :280). Every coordinate is `NodeCoord{pos, var}` meaning value(var) + pos - flat[var] (:31-35). `Add(a,b,k)` (:78-86) turns "a-b >= k" into `diff{a.var, b.var, k - (a.pos-flat[a.var]) + (b.pos-flat[b.var])}`. So a constant is spec/rule constant PLUS seed-position offsets (in-class offsets pos-flat[var]). A same-class pair is a pure constant check (:82), never a constraint.

## 2. Is the least solution independent of seed slack?

Where: `JunctionPositions::Lo()` (src/junction_positions.h:19 "Lo() is the least solution", propagation in src/junction_positions.cpp). `JunctionPositions(vars,-1024,1024)` is built, `AddJunctionNodeConstraints` called (:699-707), then Lo(c) read. DESIGN-N3 §7 (docs line 57) states: all classes at Lo is a solution of the min-closed constraints. Used at :870 for ordering.

NOT independent for a fixed structure. Slack from the seed is frozen into Lo by:
- (A) Rigid in-class offsets (1a/1b): every point of a rigid (non-free) link is one class, offsets = seed distances. A rigid run in the seed (curve, bridge span, run that is not free) keeps its seed length. Spacing the seed generously is only harmless if the long thing is a FREE run (X run joins only Y class; Y run only X class) or free diagonal.
- (B) Cross-class constants. Because Add() subtracts in-class offsets, the constants of free-link rules (1c) are independent of the run length (constant 1), but rules 1e/1g/1h/1j/1k read seed `u`, `start` and tile coordinates, and these include free-run lengths: a longer free run in the seed changes `u` and `pos diffs` in a way that cancels only on the Y-diff path of 1e (the pos difference and CeilHalf(g-u) move together if both points are in different classes): then the diff constant is `d_y*(pos_q-pos_p) + CeilHalf(g-u)` = a function of (flat_q - flat_p) and u. Extending a free Y run by e adds e to (pos difference) and subtracts e from CeilHalf(g-u) (u grows by e, rounded): constant unchanged for rule 1e. OK. For rule 1d (m_min), 1h (diagonals) the constant depends on `halves`, so a longer seed diagonal changes the constants.
- (C) Equalities: 1k (bridge crossing equality), 1l (box edges), 1n (diagonal horizontal extent = flat difference, then also a function of Y snap). 1n freezes the seed's diagonal horizontal extent into the Late phase, but `steps` (derived from the Y snap values) compensates, so the diagonal length is free via Y. D80 equal copies of doubled bridges: no explicit D80 code in the builder; the two parallel bridges are two bridges whose heads are in classes joined by the rigid links of the seed pieces, so equal lengths hold only if the seed has them equal (and the heads in the same classes).
- (D) Anchor pin (1m): anchor X and Y classes get Lo=Up=flat. Others get Lo only from lower-bound chains from the anchor; a class with no chain of >= constraints leading from the anchor keeps Lo = -1024 (the domain), so Lo is NOT a compact least layout for classes upstream of the anchor. For a least layout use the anchor-relative propagation, or free the pin (shift-normalise afterwards).
- (E) "keeps the flat T" snap preferences: `JunctionNodeSnap` (:918-934) clamps each class to `flat[c]` within [Lo,Up] (:922) for Y first (:925), then late constraints/occupancy, then X (:930). So the SNAPPED solution keeps seed slack wherever the domain permits; only Lo is slack-free (modulo A-D). Solve (:1058-1063) likewise snaps to the nearest value to flat.
- (F) Seed-read decisions that are structural but numeric: crossing membership, box edges, flat order in occupancy, signal slot positions (input.slots from seed), point set (:161-166 runs by direction change).

## 3. Where the solve reads the reference beyond constraint constants

- Y snap preference: :922 (Snap, clamp to flat[c]); :1058-1063 (Solve `snap` nearest to flat); :1284 fault x clamp to flat; 2b at :1352.
- flat_bits / tile identity: :1041-1055 builds `flat_bits[{tile}]` from seed pieces and the free run interiors at the flat values; `bits_at(piece.tile)` used at :1055, :1247, :1303, :1311, :1399. Tile bits (which tracks meet in a tile) come from the seed's tile coordinates; a seed with different tile sharing (e.g. two tracks in one tile) changes bits.
- Occupancy order: :801-806 elements record flat_row/flat_lo/flat_hi; :870-872 order by now(lo) then flat_lo, flat_hi, flat_row; :874-879 group = same flat tile and same current row (equal x); :896-905 `flat_ordered` and `gap = min(2, flat_lo_b - flat_hi_a)` when on the same flat row; otherwise 2 if tracks touch, else 1 (:905-910). So the gap on one flat row is min(2, seed gap): a seed with gap >= 2 gives 2, a gap-1 seed gives 1 (OC1). A generous seed gives gap 2 everywhere: stronger than a tight flat T.
- AddCrossings: :585-586 seed tile on the bridge line and strictly between the head coordinates along the axis; :578-581 skips paths using the bridge heads. A generously spaced seed with the same structure keeps the same sets only if bridges span the same crossings. Diagonal crossings :588-600.
- AddBoxEdges: :632-653 compares seed `pos` of path end points (min and max along each axis) and equates classes of those at the same extreme value.
- Prio sides: :367 joiner_row = row of the joiner's piece before the merge minus the merge row, seed y difference (-1, 0, +1 expected); used at :459-460 to choose the reserved row side. A spaced seed must keep the joiner adjacent (row difference sign and 0 case preserved; magnitude ignored).
- Anchor: :688-695 (which path), :706 (pinned to seed values).
- Events/slots: TraceJunctionNodeInput :656-670 (ctx from the seed layout); when input is built by hand, `events` and `slots` must be supplied by the caller (BuildJunctionNodeTemplate(const JunctionNodeInput&) :677).

## 4. Existing test/function comparing the least solution with the flat layout

- `TEST_CASE("the flat T's positions meet its template", "[junction][nodes]")` in src/tests/junction_nodes.cpp:~167-180: builds the template of the flat T, `AddJunctionNodeConstraints` on `JunctionPositions(tpl.flat.size(), -1024, 1024)`, CHECKs `Lo(c) <= flat[c] <= Up(c)` for every class and `JunctionNodeSnap(tpl, positions) == tpl.flat` ("keeps the flat T"). It compares the interval to flat, not Lo == flat, and does NOT compare Lo to the layout.
- `TEST_CASE("a longer main line between split and merge is still clean")` (src/tests/junction_nodes.cpp:~117-160): adds a longer split-merge diff, snaps, renders, runs CheckJunctionRules, CHECK(layout.size.x == flat.size.x + 2).
- Production use of Snap on the flat T topology: src/junction_generator.cpp:1950-1985 (SizeJunctionPrio) and src/tests/junction_generator.cpp:~80-90 (NodeTDelaysMainline); SearchJunctionNodes starts from `RenderJunctionNodeTracks(flat_tpl, flat_tpl.flat)` (:1685-1690).
- No function computes Lo of a template and renders it. `RenderJunctionNodeTracks(tpl, values)` (:936) accepts any values vector, so `values[c] = Lo(c)` (after the anchor/normalisation fix of 2D) can be rendered directly; Y classes must be consistent with the late diagonal constraints (Snap runs them for Y first), so a Lo-based reference needs the Snap's phase order (Y fixed, Late, Occupancy, X) or its equivalent.

## Consequence for choosing (a) vs (b')

(b') works if the seed keeps all of: the point/run/diagonal structure, same direction changes, same crossings, same box-edge alignments, same joiner row signs, same slot set, and the rigid parts at their final rigid sizes (curve legs, bridge spans, diagonal halves: 1d/1h/1n depend on halves). Free X/Y runs may be arbitrarily long (they only change reference values, constants cancel, rules 1c/1e). Fix up: free the anchor pin (2D) and expect Lo to be the least only after normalising, and note Occupancy gap = min(2, flat gap) (:903) wants seed gaps >= 2 and rows distinct. Diagonals: the seed length is frozen into m_min constants and the flat x extent, so render diagonals at their rule minimum (halves of the final structure), not generous.
